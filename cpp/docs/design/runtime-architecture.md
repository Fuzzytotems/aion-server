# Game server runtime architecture (free-threaded)

> **Status:** final design for D1 (free-threaded like Java), 2026-09-13. To be validated by the prototype plan (P1-P10) before the spine is frozen.

## Summary

The game server is free-threaded like Java. It has a packet processor pool, scheduled, instant and long-running pools, a cron thread, a ForkJoin pool for parallel movement and startup, Asio IO threads, a Reclaimer and a Watchdog. Game objects are shared through an atomic intrusive Ref<T>. Parameters and locals are borrowed Ptr<T>/T&, and they stay valid until the task ends. An epoch Reclaimer takes the place of Java's GC. A thread publishes its epoch lazily, on the first operation that loads a pointer, so a task that borrows nothing never holds up reclamation. quiescentPoint is allowed only inside an explicit QuiescentScope at task depth 1. Member declarations are derived mechanically from the Java modifiers by a generator, which now also covers late-bound parts wired through setters, captured variables of stored lambdas and anonymous classes, automatically inferred confined (non-escaping) classes, and Java equals semantics in collections. The one fatal red-team finding is fixed: ConcurrentHashMap compute callbacks and comparators now run under reentrant stripe monitors that lockdep tracks, so Java code that locks, nests map operations or calls DAOs inside compute works as it did in Java. Ranked leaf mutexes stay only in the runtime internals, which never call out. Destructors stay release-only. ID release goes through a Cleaner queue that an instant-pool task drains in a normal task scope, just like Java's Cleaner. IDs are handed out by a monotone cursor with a 300 s floor, so an ID held in a handler's list is not reused within an encounter. Cycles hidden in observers and item actions are closed in three ways: capture-aware cycle reports, callback APIs that take the same pin concepts as the scheduler, and C++ breakers that run in scope guards even when logout throws. A zombie breaker in the leak census is the last line of defence. Server packets are still serialized eagerly on the sender and queued in sequence order. Race safety comes from construction, lints, checked-build runtime checks, PCT kernel tests, a nightly stress harness and an optional Linux TSan build. Tests use a deterministic executor. Reload is deferred (D3), and waves use 4-6 agents (D4).

## 1. Threading model

### 1.1 Threads

| Thread(s) | Count (default) | Java counterpart | Runs |
|---|---|---|---|
| `main` | 1 | main | `GameServer::main` in Java order; parallel phases via ForkJoin |
| Asio IO | `gameserver.network.nio.threads` (1; >1 allowed) | NIO dispatcher | accept, read, decrypt, `readImpl`, frame/encrypt/write of serialized bytes, SM_KEY |
| `PacketProcessor:n` | 4 | same | `CM_*::runImpl`, serial per connection |
| `ScheduledPool:n` | max(4, cores) | ScheduledThreadPoolExecutor | `schedule*` bodies |
| `InstantPool:n` | max(4, cores), queue 100,000 | instant pool | `execute`/`submit`, `onDisconnect`, region activation, LS/CS packets (per-link serial), **Cleaner drain** (§6) |
| `LongRunning:n` | cached, 60 s idle | cached pool | `executeLongRunning`/`submitLongRunning` |
| `Cron` | 1 | Quartz | fire-time computation and job hand-off |
| `ForkJoin:n` | cores − 1 | commonPool | MoveTaskManager `parallelForEach`, startup `parallel()` sites |
| `Reclaimer` | 1 | GC | epochs, destruction, leak census scan (§5.4) |
| `Watchdog` | 1 | DeadLockDetector | wait graph, stalls, reclamation lag |
| `ShutdownHook` | 1 on demand | JVM shutdown hook | ShutdownHook.java:72-79 |
| logging / Discord | commons | logback | formats on the caller thread |

There are no AI, DB or geo threads: AI events are synchronous, DAOs run inline, and geo is immutable with atomic door bitsets.

### 1.2 Task scopes

```cpp
namespace aion::gameserver::runtime {
struct TaskInfo { std::source_location where; const char* kind; };

/** RAII, opened by every entry point: pool workers, PacketProcessor decorator, AionConnection strand callbacks, cron runners, ForkJoin
 *  helpers, startup and shutdown phases. Nested scopes only increment a depth counter. Entry records the scope id and TaskInfo; the epoch is
 *  NOT published here but lazily by the first pointer-loading operation (§2.4). */
class TaskScope {
public:
	explicit TaskScope(const TaskInfo& info) noexcept;
	~TaskScope();
	static bool active() noexcept;
	static uint32_t depth() noexcept;
	static uint64_t currentScopeId() noexcept;   // Ptr stamps
	static void ensurePublished() noexcept;      // called by read barriers; cheap when already published
};

/** Marks a block, opened directly in a task body (depth 1, not a joined ForkJoin helper), whose enclosing frames hold only Refs, pinned
 *  captures and immortals. Required for quiescentPoint(). */
class QuiescentScope { public: explicit QuiescentScope(std::source_location = std::source_location::current()); ~QuiescentScope(); };

/** Inside a QuiescentScope: unpublishes the epoch and starts a new scope id (older Ptr stamps throw in checked builds).
 *  Anywhere else: no-op, plus a once-per-site warning in checked builds. */
void quiescentPoint() noexcept;

/** RAII around blocking waits (Future::get, Semaphore::acquire, DB getConnection/execute, NioServer::openSocket). Feeds the watchdog;
 *  does not unpublish. */
class BlockingRegion { public: BlockingRegion(const char* what, std::source_location = std::source_location::current()) noexcept; ~BlockingRegion(); };
}
```

The rule "anything reached during a task stays readable until the task ends" applies on every registered thread, IO threads included.

### 1.3 Handing work between threads

There is no message passing. Closures holding `Ref`s move work: packet → PacketProcessor, anything → `ThreadPoolManager`, cron → runner, `sendPacket` → bytes → connection queue → IO strand, IO → `onDisconnect` → instant pool.

### 1.4 Threading deviations

- `nio.threads > 1` is allowed. The two `readImpl` log reads (CM_BUY_ITEM:48, CM_ATREIAN_PASSPORT:33) move to `runImpl`.
- LS/CS link packets run in order per link.
- Cancelled tasks release their captures immediately.
- Fixed-rate tasks more than `gameserver.scheduler.coalesce_after` periods behind (10, and at least 2 s) run once and realign.
- Cron jobs that trigger shutdown post to the ShutdownHook thread and return, instead of blocking in scope (Java already starts a separate thread, ShutdownHook.java:91).

### 1.5 Blocking sites stay blocking

- **CM_TELEPORT_ANIMATION_DONE.java:36-41:** `task->run(); task->get();`
- **FixPath.java:143-152:** `get(5, SECONDS)` inside a `BlockingRegion`. The route loop (FixPath.java:85-133) opens a `QuiescentScope` and calls `quiescentPoint()` at the top of every step, so reclamation is not pinned for minutes (RR-7).
- In `single_executor` mode, `get()` on the executor thread runs due tasks until done or timeout.

### 1.6 Debug modes

- `gameserver.debug.single_executor`: every pool, the PacketProcessor and cron run on one thread; `parallelForEach` is sequential.
- `gameserver.debug.serial_movement`: movement only is sequential.

## 2. Lifetime core

### 2.1 Reference kinds

| Kind | Type | Storable | Use |
|---|---|---|---|
| Owning | `Ref<T>` | yes | fields, containers, captures, packet members |
| Borrowed | `Ptr<T>` / `T&` | no | parameters, locals, returns |
| Non-final field | `Field<T>` | n/a | §3 |
| Final | `const T` / `Final<T>` | n/a | Java final and effectively final |
| Part | `const std::unique_ptr<P>` / `PartSlot<P>` / `PartMap<K,P>` / `PartList<P>` | n/a | owner-created sub-objects |
| Part → owner/sibling | `OwnerRef<O>` / sibling raw pointer | n/a | never retains |
| Owner-or-foreign | `SelfOrRef<O>` | n/a | a part field that holds either its own owner (non-retaining) or a foreign object (retaining) (RR-5) |
| Template | `const T*` | yes | immortal static data |
| Connection | `std::shared_ptr<AionConnection>` | yes | commons convention |
| Confined object | plain members, `Ptr`/`T&` | no | K5 classes (§3.1), stack or `std::unique_ptr` |

`Ref`, `Ptr` and `Field<Ref>` throw `NullPointerException` on a null dereference.

### 2.2 API sketch

```cpp
namespace aion::gameserver::runtime {

class RefCounted {
public:
	RefCounted(const RefCounted&) = delete; RefCounted& operator=(const RefCounted&) = delete;
	void retain() const noexcept;      // fetch_add; 0->1 legal (resurrection); checked: cookie == ALIVE (set only by makeRef)
	void release() const noexcept;     // fast path: CAS c -> c-1 while c > 1 (no stamp); at 1: stampRetireEpoch() then CAS 1 -> 0; retry on failure
	Monitor& monitor() const noexcept { return monitor_; }
protected:
	RefCounted() noexcept = default;
	virtual ~RefCounted();             // protected in every subclass (generated); only the Reclaimer deletes
private:
	friend class Reclaimer; template <class T, class... A> friend Ref<T> makeRef(A&&...);
	mutable std::atomic<uint32_t> count{0};
	mutable std::atomic<bool> queued{false};
	mutable std::atomic<uint64_t> retireEpoch{0};
	mutable Monitor monitor_;
#if AION_CHECKED
	mutable std::atomic<uint32_t> cookie{UNMANAGED};   // UNMANAGED -> ALIVE (makeRef) -> DEAD
#endif
};

struct Immortal { Monitor& monitor() const noexcept; };

template <class T> class Ptr { /* as before: NPE, checked scope stamp; T* p; uint64_t scope (checked) */ };
template <class T> class Ref { /* as before: retain/release, conversions to Ptr, identity == */ };

template <class T, class... A> Ref<T> makeRef(A&&... a);   // the only way to construct a RefCounted (T::create forwards here)
template <class To, class From> Ptr<To> cast(Ptr<From>);  // ClassCastException
template <class To, class From> Ptr<To> as(Ptr<From>) noexcept;

class Reclaimer {
public:
	static Reclaimer& getInstance();
	void start(std::chrono::milliseconds period);          // reclaim_period_ms = 20; woken at backlog > 8192
	static void retire(const RefCounted& o) noexcept;
	static void retirePart(const RefCounted& owner, std::unique_ptr<OwnedPartBase> part) noexcept; // PartMap/PartSlot(RECLAIM), §2.3
	void reclaimNow();                                     // deterministic executor
	struct Stats { uint64_t epoch, minActive, backlog, backlogBytes, destroyedTotal; std::chrono::milliseconds lag; TaskInfo oldestPublishedTask; };
	Stats stats() const;
};
}
```

**Stack instances are impossible (RR-12).** Generated RefCounted subclasses have protected destructors and a `static Ref<T> create(...)`. `QuestEnv env(...)` does not compile. In checked builds, `retain()` on an object whose cookie is `UNMANAGED` terminates with the class name. K5 confined classes are plain value types and may live on the stack.

### 2.3 Parts

```cpp
class OwnedPart {
public:
	void retain() const noexcept;  void release() const noexcept;   // forward to owner (checked: owner bound)
	const RefCounted& partOwner() const noexcept;
protected:
	explicit OwnedPart(const RefCounted& owner) noexcept;           // owner known at construction
	OwnedPart() noexcept = default;                                  // late-bound (controllers): bindOwner before publication
	void bindOwner(const RefCounted& owner) noexcept;                // once; checked: owner not yet published (count <= 1), not rebound (C11)
};
template <class O> using OwnerRef = O&;

enum class RetireTo : uint8_t { OWNER, RECLAIMER };

/** Replaceable single part. OWNER: old parts are kept in the owner's retired list until the owner dies (Creature.ai; replacements are rare).
 *  RECLAIMER: old parts are handed to Reclaimer::retirePart, which holds a Ref to the owner, stamps the current epoch and destroys the part
 *  once no task that could have borrowed it is active (Player storages, Account.accountWarehouse: replaced on every stale-online re-entry). */
template <class P, RetireTo R = RetireTo::OWNER> class PartSlot {
public:
	P* get() const noexcept; P& operator*() const; P* operator->() const;   // pointer load: read barrier (ensurePublished)
	void set(std::unique_ptr<P> part);
};
/** Map of parts (Account.players -> PlayerAccountData). put/remove retire the old part to the Reclaimer (RR-11). */
template <class K, class P> class PartMap { public: Ptr<P> get(const K&) const; void put(K, std::unique_ptr<P>); bool remove(const K&); /* snapshot iteration */ };
/** Append-only part list with stable addresses (SpawnGroup templates). */
template <class P> class PartList;

/** Part field of the owner's type that sometimes points at the owner itself (inventory.actor == owner) and sometimes at a foreign object
 *  (account warehouse actor == the entering Player). On store: identity with partOwner() -> tagged non-retaining; otherwise retaining. */
template <class O> class SelfOrRef { public: Ptr<O> get() const; void set(Ptr<O> value); /* same API as Field<Ref<O>> */ };
```

`TargetField` (RT-4) is `SelfOrRef<VisibleObject>` on VisibleObject. As built (S0b): used as designed; a `fieldmap.toml` override makes

### 2.4 Reclaimer protocol

**State.** Global epoch `E`. Per thread `active` (published epoch or IDLE). Per object `count`, `queued`, `retireEpoch`.

**Lazy publication (RR-4).** `TaskScope` entry does not publish. Every pointer-loading operation calls `ensurePublished()` first:
```
if (active == IDLE) do { e = E.load(); active.store(e); } while (E.load() != e);
```
Pointer-loading operations are `Field<Ref>::get/->/*`, `Field<std::string>::get`, `SelfOrRef::get`, `PartSlot/PartMap::get`, shim `get`/iteration/snapshot, `Array` slot reads of references and `ConcurrentHashMap` lock-free reads. Reaching an object through a `const Ref` member, a captured `Ref`, a `Pin` or an immortal needs no publication, because those references are retained and never change. A Ptr can only exist after publication, so `Ref(Ptr)` needs no barrier. Outermost scope exit and `quiescentPoint()` store IDLE and flush the thread-local retire list.

**release()**. While `count > 1`: CAS decrement, no stamp. At `count == 1`: `retireEpoch = max(retireEpoch, E)` (CAS loop), then CAS 1→0. If it succeeds and `!queued.exchange(true)`, push.

**Scan.**
1. `E.fetch_add(1)`.
2. `m = min(E, every published active)`, computed before reading any object.
3. For each queued object: if `count == 0 && retireEpoch < m`, delete. Else if `count > 0`, clear `queued`; then if `count == 0 && !queued.exchange(true)` keep it. Else keep.
4. Same rule for retired parts (`retirePart` entries carry their stamp).

**Safety sketch.** Suppose O is freed while thread X can still dereference it.
- X obtained its pointer by a load (after publishing `e_X`) from a location holding a Ref, or through a retained chain from such a load.
- Any location X loaded from is unlinked after the load. The last 1→0 transition follows every such unlink, and it stamps with E read after the unlink, so `retireEpoch ≥ e_X`. Skipping the stamp on `c > 1` releases does not weaken this: only the final transition must follow X's load.
- A retained chain (const Ref, capture) keeps `count > 0` for as long as its holder lives, and the holder is protected by the same argument.
- If X published before `m` was computed, `m ≤ e_X ≤ retireEpoch`. If X published after, it loaded after the scan's `E` increment, hence after the unlink of any location that no longer holds O, so it could not have obtained O (resurrection needs an older borrow, which implies an earlier publication).
- Cascades in destructors are stamped at the current epoch and wait one cycle per level.

**Unregistered threads.** Pointer-loading operations assert `TaskScope::active()` in checked builds (C2). `retain`/`release` are legal everywhere.

### 2.5 Costs (est., x64, uncontended)

| Operation | Cost |
|---|---|
| `Ref` copy / non-final release | 1-3 ns (`lock xadd` / CAS, no stamp) |
| last release | ~5 ns (stamp + CAS) |
| `Ptr` copy/deref | 0 (+1 predicted branch) |
| scope enter/exit | ~3 ns; publication ~5 ns once per scope |
| `Field<float>` load | `mov` |
| `Field<Ref>` load | TLS check + `mov` |
| Monitor | ~20 ns |
| ConcurrentHashMap get | lock-free, ~10-20 ns |
| ArrayList/HashMap shim op | ~30-60 ns |
| snapshot of 300 pointers | < 1 µs |
| `RefCounted` memory | +40 B per object |

### 2.6 Long and stuck tasks

- A task pins reclamation only from its first pointer load to its end. Geo collision builds, NN training, pure DAO tasks and blocked cron runners do not pin at all (RR-4).
- Loops that touch many objects in one task open a `QuiescentScope` and call `quiescentPoint()` per element: `PeriodicSaveService`, shutdown saves, the `spawnAll` top loop, FixPath route steps, QuestSpawnAnalyzer per quest.
- `quiescentPoint()` is a no-op unless all of these hold (RR-6): a `QuiescentScope` is open, `TaskScope::depth() == 1`, and the thread is not a joined ForkJoin helper. Checked builds warn once per `source_location` on a no-op call.
- `parallelForEach` has `Isolation::JOIN` (default: helpers share the submitter's scope id, Ptrs valid) and `Isolation::PER_ELEMENT` (element type must be `Ref<T>`, immortal pointer or value; each helper opens its own scope per element). `spawnAll` per map uses PER_ELEMENT.
- **Metrics and alarms.** `Reclaimer::Stats.lag` and the oldest published scope. The watchdog warns when lag > 10 s and dumps the pinning task's `TaskInfo` and current `BlockingRegion` when backlog > `gameserver.runtime.backlog_dump_objects` (1,000,000) or > 256 MB.
- **DB.** The game server requires a non-zero `database.socket_timeout` (default 60 s); startup fails otherwise. DAO calls run inside `BlockingRegion`.

### 2.7 Destructors

- `noexcept`, release-only: drop Refs, push the object id to the Cleaner queue (§6), log ids.
- Forbidden: dereferencing Ref/Ptr/Field, container calls, packets, events, Monitors, service calls. The Reclaimer sets a destructor context in which a dereference terminates with class name and stack (C8).
- Parts are destroyed by their owner's destructor or by `retirePart`.

Implementation notes (`fieldmap.py`, wave 1):
- `OwnerRef` vs `SelfOrRef` comes from a whole-tree write scan: an owner field is `SelfOrRef` only if something other than the constructors and instance initializers of the part class and its subclasses writes it (a qualified write to a non-private field matches by name, conservatively). Today only `PlayerStorage.actor` is `SelfOrRef`.
- A captured `this` becomes `OwnerRef` only when every storage owner of the callback is the captured class or a subtype (Effect's anonymous observers are stored in the effected creature's ObserveController, so they capture `const Ref<Effect>`).
- Element writes (`arr[i] = v`, `arr[i]++`) never make an array field non-effectively-final.

#### 3.2.1 Part detection (RR-9)

A field F of owner O holding type X is a part when the evidence matches any of these patterns, each recorded in `parts.json` with its source line:
1. `final X f = new X(this…)`, or `f = new X(this…)` in O's constructor.
2. `setF(new X(this…))` in a constructor of O or of a subclass (Npc.java:70-71, Homing.java:29-36, Kisk.java:51-52), or `r.setF(new X(r…))` anywhere on a freshly created `r` before `World.storeObject`/spawn (VisibleObjectSpawner.java:60-250, PvpMapHandler.java:167-169). F becomes `PartSlot<X>` (a non-final field with a setter).
3. **Late-bound controllers:** `super(..., new XController(), ...)` or `new O(new XController(), ...)` plus `controller.setOwner(this)` in O's constructor (VisibleObjectController.java:20-28, Npc.java:58). X derives `OwnedPart` with `bindOwner`; its `owner` field becomes `Final<O*>` exposed as `OwnerRef`.
4. `fieldmap.toml` overrides with a reason (PlayerAccountData, Account storages, SpawnTemplate).

S0b reviews the generated `parts.json` and does not hand-write these members.

### 3.3 Collections and arrays

```cpp
namespace aion::gameserver::runtime {
/** Plain Java collections (ArrayList, LinkedList, ArrayDeque, HashMap, LinkedHashMap, TreeMap, HashSet, LinkedHashSet, TreeSet, EnumMap,
 *  PriorityQueue). One reentrant collection Monitor (lock class Owner::field) guards every operation, including callbacks (comparators,
 *  compute, removeIf predicates), exactly like Java code that wraps them in synchronized. Iteration uses snapshots. */
template <class T> class ArrayList {
public:
	void add(T value); void add(int32_t index, T value);
	Borrowed<T> get(int32_t index) const; void set(int32_t index, T value);
	Borrowed<T> removeAt(int32_t index);
	bool remove(const Borrowed<T>& value);             // Java equals semantics (below)
	bool contains(const Borrowed<T>& value) const; int32_t indexOf(const Borrowed<T>& value) const;
	int32_t size() const; bool isEmpty() const; void clear();
	bool removeIf(std::predicate<Borrowed<T>> auto&& p); // under the collection Monitor, evaluated on the live list (Java order)
	void sort(auto&& comparator);                        // under the collection Monitor; comparator may take Monitors (lockdep-tracked)
	JavaIterator<T> iterator() const;                    // hasNext/next/remove over an owned snapshot; remove() deletes the last returned element by identity
	SnapshotIterator<T> begin() const; std::default_sentinel_t end() const noexcept;
	std::vector<Borrowed<T>> snapshot() const;
	Monitor& monitor() const noexcept;                   // synchronized (list)
};

/** ConcurrentHashMap: 16 stripes. Readers (get, containsKey, iteration) are lock-free over EBR-retired node tables and iterate in place,
 *  weakly consistent, without snapshots (RR-17). Writers take the stripe's reentrant StripeMonitor (rank 0, lock class Owner::field#stripe).
 *  compute/computeIfAbsent/computeIfPresent/merge run their callback while holding that StripeMonitor: the callback may take Monitors, call
 *  other map operations (different keys, including the same stripe, through reentrancy), schedule, cancel, send packets or call DAOs,
 *  as Java allows (RR-1). A recursive update of the same key throws IllegalStateException("Recursive update"), as Java does. */
template <class K, class V> class ConcurrentHashMap;
// Same pattern: ConcurrentHashMap::newKeySet, CopyOnWriteArrayList (atomic Ref to an immutable vector, lock-free reads and iteration),
// ConcurrentLinkedQueue (lock-free), ConcurrentSkipListMap (if used; stripe-less writer Monitor).
// Every shim has a RefCounted variant (RcArrayList<T> = RefCounted + ArrayList<T>) so it can be a map value or Field<Ref<...>> target.

template <class T> class Array : public RefCounted { /* fixed length, Field<T> slots, AIOOBE */ };
}
```

- **Java equality (RR-13).** `remove(Object)`, `contains`, `indexOf`, and the keys of HashSet/HashMap/TreeSet use the element's Java `equals`/`hashCode`/`compareTo` when the Java class or a superclass other than Object overrides them. `fieldmap.json` records `hasEquals` per class. `AionObject` gets `equals` on objectId and `ObjectIdHash`. Classes without an override use identity. `JavaIterator::remove` stays identity (positional in Java). DropNpc.java:122-134, SiegeService.java:684 and AutoHarmonyInstance.java:75 therefore behave as in Java across relogin.
- **Fast paths.** `isEmpty()` is a lock-free atomic size read. Hot notifiers (ObserveController) check it before snapshotting, as Java does.
- **Locals stay `std::`.**
- **Re-entrant modification during iteration** is memory-safe. Deviation: no `ConcurrentModificationException`.

## 4. Locks, ordering and deadlocks

### 4.1 Two lock families

1. **Game-level Monitors (rank 0):** object monitors, collection Monitors, ConcurrentHashMap stripe monitors, `Monitor` members, StampedLock/Semaphore shims. They may nest arbitrarily and call out, as in Java. Ordering is checked by the lock-order validator.
2. **Leaf mutexes** (`RankedMutex<R>`): internal to `runtime/` and `network/` only. They never run user callbacks, never take a Monitor and never block on IO.

```cpp
enum class LockRank : uint8_t { CONTAINER_SLOT = 10, CONNECTION_QUEUE = 20, SCHEDULER = 30, IDFACTORY = 40, RECLAIMER = 50, STATS = 60, LOGGING = 90 };
```

- `CONTAINER_SLOT` protects only node-table resizing inside ConcurrentHashMap (writers already hold the stripe Monitor) and the ZoneName intern table.
- Checked **and** release builds: acquiring rank r requires max held leaf rank < r, and acquiring any Monitor while a leaf mutex is held throws `IllegalStateException`. This can only fire on a runtime bug, never on ported Java code, because no user code runs under a leaf mutex.
- The judges' chain `CHM.compute` → `cancel` → heap → reclaimer → logger becomes stripe Monitor → lock-free cancel → lock-free retire → LOGGING leaf: legal.
- `CreatureGameStats.java:73-84` (compute → `synchronized (statFunctions)`), `PlayerContainer.java:51-54` (put inside compute), `GaleCycloneAI.java:31-35`, `LegionService.java:154-159` (DAO inside computeIfAbsent), `SpawnsData.java:83-96` (nested compute) and `Preview.java:211-226` all port as written. They are conformance tests in P1.

### 4.2 Lock-order validator (checked builds)

- Per-thread held-lock stack of lock classes. A new edge A→B is recorded with its first stack; a DFS looks for B→A.
- A cycle is reported once with both stacks as `log.error`; `failOnReport` makes CTest fail.
- Same-class nesting (Player A then Player B, stripe #3 then #3 through reentrancy is not nesting) is a warning.
- Blocking under a Monitor (`Future::get`, DB calls, Semaphore) is counted and listed by `//debug locks` as a warning.
- Suppressions need a `// lockdep: <reason>` at the site.

### 4.3 Watchdog

- Each Monitor/RankedMutex wait records `{thread id, lock class name (copied), owner thread id (copied), waitStart}`. The watchdog never dereferences the lock object (RR-15).
- A cycle in the wait graph → dump of threads, TaskInfo, held lock classes, `BlockingRegion`, stacks, minidump.
- Slow-task warning past `ThreadConfig::MAXIMUM_RUNTIME_IN_MILLISEC_WITHOUT_WARNING`; dump past `gameserver.watchdog.stall_seconds` (60).
- Exit with RESTART only if `gameserver.watchdog.restart_on_deadlock=true`. Disabled while `IsDebuggerPresent()`.

### 4.4 Relation to Java's graph

The Monitor graph is Java's, including CHM bin locks (a stripe covers more keys than a Java bin, which adds only edges between different keys on one stripe; these are reentrant for the same thread, and cross-thread cycles through two stripes need two maps, as in Java). Eager serialization removes guard → monitor edges. Deadlocks are as possible as in Java.

### 5.3 Cycles

**Capture-aware type-level report.** `fieldmap.py` builds the graph of retaining edges from:
- declared `Ref`/`Field<Ref>`/container fields;
- **stored callbacks** (RR-2/RR-3): for each lambda or anonymous class passed to a storing API (`addObserver`, `attach`, `addAttackCalcObserver`, `putRequest`, `addOnEventEndTask`, `CronService.schedule`, `DeathObserver` construction, field assignment, `schedule*`), edges from the storing container's owner class to each captured variable's type, labelled with the source line;

### 5.4 Leak census and stale pins

- `LeakCensus` runs **on the Reclaimer thread**, between scans, the only place objects are freed (RR-15). `World.removeObject` pushes `{RefCounted*, class name, objectId, time}` to a lock-free MPSC queue. The Reclaimer moves entries into its private table, and `delete` on the Reclaimer thread erases an object's census entry before freeing, so the raw pointer never dangles. The scan reads only `count`.
- Objects alive after `gameserver.debug.leak_census_minutes` (10) are reported with class, id, refcount and the `source_location` of every pending task pinning them (the pin index is a leaf-ranked table owned by the scheduler; the census copies strings). `//debug leaks` shows the list. The zombie breaker is fed from the same table.
- Scenario tests assert zero after `destroyInstance`, logout (plain, with a polished weapon, during a 5 s item use, with a DAO exception), alliance disband, kisk expiry and 50 stale-online re-entries.
- A periodic task whose pins have all been removed from World for more than 10 minutes is logged once. It is not cancelled.

## 6. ID lifecycle

| Group | Objects | Release |
|---|---|---|
| (a) auto-release | Npc, Gatherable, StaticObject, Summon, HouseObject, teams | `~AionObject` pushes the id to `CleanerQueue` (lock-free MPSC). A `CleanerDrain` task on the instant pool, posted by the Reclaimer after each scan with a non-empty queue, runs the Java Cleaner body in a normal TaskScope: `if (!RespawnService::setAutoReleaseId(id)) IDFactory::releaseId(id)` (AionObject.java:31-34, RespawnService.java:95-100,201-226, including its `SYNCHRONIZED` handoff with `unregister`) (RR-1) |
| (b) explicit | Items after DB delete, exchange, split, pets, HTML, create character | same call sites |
| (c) never | FlyRing, Road, CuringObject, AssembledNpcPart | never |
| (d) DB-owned | players, legions, mail, houses | never by lifetime |

**Reuse policy (RR-10).**
- `IDFactory::nextId` allocates from a **monotone cursor**: `nextMinId` never moves down on release. When the cursor passes `gameserver.idfactory.wrap_at` (default 2^27, 16 MB of bits), it wraps to the lowest free id. The reuse interval becomes free space divided by the allocation rate (days), so bare-int holders like SummonerAI.java:73-90 and `Npc.creatorId` do not hit reused ids during an encounter.
- Released ids also sit in a FIFO for at least `gameserver.idfactory.release_delay` = 300 s (covers `DecayTask` with drops, RespawnService.java:35,59) before their bit is cleared, including after a wrap.
- Checked builds log a warning in `World.storeObject` when an id released less than 1 h ago is reassigned, naming the previous class.
- `World.removeObject` and `RespawnTask` keep their identity checks. The client treats ids as opaque (DEVIATION).

## 7. Scheduler, Future, cron, ForkJoin

### 7.1 API

```cpp
namespace aion::gameserver::utils {
enum class TimeUnit { NANOSECONDS, MICROSECONDS, MILLISECONDS, SECONDS, MINUTES, HOURS, DAYS };

class Future final : public runtime::RefCounted {  // PENDING -> RUNNING -> {PENDING periodic | DONE | FAILED}; PENDING|RUNNING -> CANCELLED
public:
	bool cancel(bool mayInterruptIfRunning = false) noexcept; // lock-free CAS
	bool isCancelled() const noexcept; bool isDone() const noexcept; bool isPeriodic() const noexcept;
	int64_t getDelay(TimeUnit unit = TimeUnit::MILLISECONDS) const noexcept;
	void run();

	void get(int64_t timeout, TimeUnit unit);

using FutureRef = Ref<Future>;

class Pin { /* retains up to 4 owners: RefCounted, OwnedPart (owner), Immortal (checked registered) */ };

template <class T> concept TaskArg = std::is_arithmetic_v<T> || std::is_enum_v<T> || IsRef<T> || std::same_as<T, FutureRef>
	|| std::same_as<T, std::string> || IsTemplatePtr<T> || IsImmortalPtr<T> || IsSharedPtrToConst<T> || std::same_as<T, std::weak_ptr<AionConnection>>;

template <class F> concept UnpinnedTask = std::convertible_to<F, void (*)()>
	|| (std::derived_from<std::remove_cvref_t<F>, TaskStruct> && AllFieldsAre<std::remove_cvref_t<F>, TaskArg>) || IsBoundTask<std::remove_cvref_t<F>>;
template <class F, TaskArg... A> auto bindTask(F captureless, A&&... args);

/** Type-erased stored callback with the same capture rules as tasks (RR-3): PinnedCallback<Sig>(Pin, invocable) or
 *  PinnedCallback<Sig>(UnpinnedTask-like callable). Used by ActionObserver lambdas, DeathObserver, RequestResponseHandler, CronService
 *  jobs, Event end tasks. Anonymous Java classes become generated named structs deriving the Java base with TaskArg/OwnerRef members. */
template <class Sig> class PinnedCallback;

class ThreadPoolManager final {
public:
	static ThreadPoolManager& getInstance();
	FutureRef schedule(Pin pin, std::invocable auto&& task, int64_t delay, TimeUnit unit = TimeUnit::MILLISECONDS, std::source_location = std::source_location::current());
	FutureRef schedule(UnpinnedTask auto&& task, int64_t delay, TimeUnit unit = TimeUnit::MILLISECONDS, std::source_location = std::source_location::current());
	template <class Self> FutureRef schedule(Self* self, void (Self::*method)(), int64_t delay, std::source_location = std::source_location::current());
	// scheduleAtFixedRate: same forms (+ invocable<Future&>); execute/executeLongRunning/submit/submitLongRunning: pinned and unpinned forms
	std::vector<TaskInfo> tasksPinning(const runtime::RefCounted& owner) const;
	std::vector<std::string> getStats() const;
	void shutdown();
	static void installBackend(std::unique_ptr<ExecutorBackend> backend);
};
}
```

### 7.2 Semantics

- ScheduledPool: one `(due, seq, FutureRef)` heap behind a SCHEDULER leaf mutex; cancel is a CAS; purge when shells exceed 50%.

- Exceptions as ThreadPoolManager.java:51-79.
- Instant pool rejection: warn, then a new thread above normal priority, else run on the caller.
- Every task runs in a `TaskScope` with its `source_location` (slow-task warnings, stats, watchdog, `//tasks`).

## 8. Server packets

### 8.1 Model

Packets are serialized eagerly on the sending thread, outside connection locks. IO threads frame, encrypt and write. This fixes RT-6 and samples state right after the sender's own mutations.

### 8.2 API

- A broadcast serializes a SHARED packet once, on the first eligible recipient (`SerializedPacket once`).

### 8.4 Ordering and consistency

- Each connection queue is ordered by `seq` sampled at serialization start. A thread's own sends keep call order; across threads the later-started serialization is written later.
- Residual: a serialization spanning another thread's whole mutate-and-serialize can still precede newer state (sub-millisecond; the next update corrects it). Accepted.
- Reads are memory-safe; multi-field consistency is Java's race; the sender's own mutations are always included.

### 8.6 IO path

`writeData` on the strand pops the front, writes length and body, encrypts, applies `enablesCrypt`. Crypt state is strand-only. The membership-10 packet-name echo runs at serialization on the sender.

### 8.7 Checks

A SHARED packet dereferencing `con` throws NPE with the packet name. In checked builds, `getActivePlayer()`/`getAccount()` from an unflagged packet's `writeImpl` throws `IllegalStateException` (C9).

### 12.3 Review checklist

- **R1** Java locks mapped; no new locks outside `runtime/`.
- **R2** Retaining fields and **stored callbacks** have `cycles.toml` resolutions.
- **R3** Tasks and callbacks: pins, captures, survival after owner deletion as Java.
- **R4** Waivers justified.
- **R5** No new check-then-act where Java had one atomic operation.
- **R6** Destructors release only.
- **R7** Packets: recipients, `Ref` members, no mutation in cached packets.
- **R8** IO-thread paths open a scope, no game logic.
- **R9** Long loops use QuiescentScope with Ref snapshots; long blocking waits are inside BlockingRegion.
- **R10** Periodic tasks end or document why.
- **R11** Lockdep reports empty.
- **R12** New breakers go into `LogoutBreakers`/`onDelete`, never at the end of a function without a guard.

## 14. Porting mechanics

### 14.1 Rules at a glance

1. **Members come from `fieldmap.py`** (declared fields, parts, callback structs, confined classes). Copy or verify.
2. **References:** parameters/locals/returns `Ptr<T>`/`T&`; stored `Ref<T>`. K4 objects are created with `X::create(...)`, never on the stack; K5 classes are plain values.
3. **Collections:** same-named shims for fields, `std::` for locals; `for (Ptr<X> x : list)`; `Iterator` loops → `auto it = list.iterator(); while (it.hasNext()) { … it.remove(); }`.
4. **Locks:** `SYNCHRONIZED(x)`; Java lock classes → same-named shims; code inside `compute` ports as written.
5. **Tasks and stored callbacks:** `this::m` → `this, &X::m`; lambdas pin `this` and `&x`; anonymous classes → the generated named struct; `addObserver(new ActionObserver(){…})` → `addObserver(IdianStoneActionObserver::create(player, …))`.
6. **Packets:** `new SM_X(...)` → `SM_X(...)`.
7. **Casts and identity:** `cast<Npc>(x)`, `as<Npc>(x)`, `a->equals(*b)`, `a == b`, `delete()` → `delete_()`.
8. **Long work:** loops over many objects open a `QuiescentScope`; cleanup that must always run goes into a `finally` guard.

## 15. Performance and debuggability

### 15.1 Performance (est., measured in P2/P4)

- 60-100k objects ≈ 150-300 MB; static data 300-500 MB; geo ~300 MB.
- Movement tick with 2,000 movers ≈ 2-6 ms CPU across cores − 1.
- Refcount traffic: KnownObject churn and packet construction. Non-final releases skip the epoch stamp; transient stat objects are K5 and do no refcounting.
- Hot reads (KnownList iteration, World lookups, observer lists) are lock-free on ConcurrentHashMap/CopyOnWriteArrayList with `isEmpty` fast paths. Plain ArrayList/HashMap shims still snapshot; P4 measures them and hot ones can be switched to CopyOnWrite variants via a `fieldmap.toml` override (DEVIATION-free: same Java-visible semantics).
- Checked build overhead 10-30%; P4 requires p99 < 50 ms per tick in the checked build.

### 15.2 Debuggability

- Exceptions carry `std::stacktrace`; NPEs are real exceptions.
- `source_location` on every task, callback and blocking region.
- Watchdog dumps with natvis for Ref/Ptr/Field/shims plus a minidump.
- Deterministic reproduction: DeterministicExecutor, `single_executor`/`serial_movement`, PCT seeds.
- Deadlocks show up as lock-order reports in tests.
- A breakpoint stops one thread; the watchdog is off under a debugger, coalescing prevents floods, and lazy publication means a paused borrow-free thread does not pin memory.
- Java's own races remain nondeterministic in production.

## 23. Spine step S0a: kernel lifecycle and fixes (2026-09-14)

Spine step S0a wired the kernel services into one start/shutdown sequence and closed kernel open items (status:
[spine-status.md](spine-status.md), [runtime-kernel-status.md](runtime-kernel-status.md)). The header comment of
`runtime/services/RuntimeLifecycle.h` is authoritative.

### 23.1 `RuntimeLifecycle` (`aion_gs_runtime_services`, namespace `aion::gameserver::runtime`)

Static `start(Options)`, `shutdown()` returning a `ShutdownReport {performed, tasksLeft, cleanerIdsDrained, reclaimerBacklog, censusTracked}`,
`getState()`/`isRunning()` (`NEW, STARTING, RUNNING, STOPPING, SHUT_DOWN`) and `resetForTests()`. No Java counterpart: it bundles the kernel
part of `GameServer.initUtilityServicesAndConfig` and `IDFactory.getInstance()`, the tail of `ShutdownHook.run`, and the C++-only services.

**Start order** (called after `Config.load`, `DatabaseFactory.init` and `PlayerDAO.setAllPlayersOffline`, Java order):
1. Reclaimer: configure, start its thread.
2. LeakCensus configure and install; CleanerQueue cleaner action and install (their Reclaimer hooks exist before the first game object).
3. Watchdog start (Java starts `DeadLockDetector` in the ThreadPoolManager constructor, before the pools).
4. ThreadPoolManager: configure, then install `Options::backend` or create the default pools ("ThreadPoolManager: Initialized with ...").
   A backend installed before `start()` (or pools created lazily by earlier code) is retired first, with a warning unless it was already
   shut down. ForkJoin serial mode is set.
5. `CronService.initSingleton(ThreadPoolManagerRunnableRunner, time zone)`.
6. IDFactory: configure, `lockIds(0)`, then each `UsedIdsSource` in Java `initializeUsedIds` order (PlayerDAO, InventoryDAO,
   PlayerRegisteredItemsDAO, LegionDAO, MailDAO, GuideDAO, HousesDAO, PlayerPetsDAO), then "IDFactory: N IDs used.".

If a step throws, the finished steps are undone as in `shutdown()`, the state becomes `SHUT_DOWN` and the exception propagates.

**Shutdown order** (called by the ShutdownHook after its game steps, §11):
1. `CronService.shutdown()` (pending jobs dropped, their pins released).
2. `ThreadPoolManager.shutdown()` (delayed tasks cancelled, running and queued tasks get 5 s).
3. Final CleanerDrain (§11 step 6): the CleanerQueue hook is removed, then `Reclaimer::drain()` and `CleanerQueue::drainNow()` alternate until
   no id is left.
4. LeakCensus check: objects removed from the world that are still alive are counted and reported.
5. Watchdog and Reclaimer threads are stopped if `start()` started them; LeakCensus is uninstalled.

Each step logs and swallows its own exception, so the later steps still run. `Logging::shutdown` and `quick_exit` stay with the caller.

**Rules.**
- One run per process: `start()` only in state `NEW` (`IllegalStateException` otherwise, also after `shutdown()`); only `resetForTests()`
  returns to `NEW`. `CronService.initSingleton` and IDFactory seeding cannot run twice without their test resets.
- `shutdown()` acts only in state `RUNNING`; otherwise it returns `performed == false` (second call, call before start, concurrent shutdown).
  `start`, `shutdown` and `resetForTests` are serialized by one mutex; `getState` is lock-free.
- `shutdown()` must run outside any `TaskScope`, otherwise it throws `IllegalStateException`: the final drain cannot free objects the calling
  task borrowed. Pool tasks and cron jobs run inside scopes, so they post the shutdown to the ShutdownHook thread (§1.4). `start()` may run
  inside a STARTUP/MAIN scope; the used-ids sources run on the calling thread.
- After shutdown the shut-down backend stays installed, so late submissions are cancelled instead of creating new pools. The ForkJoinPool
  helpers are not shut down (Java's `commonPool` is never shut down).
