# Deviations of chunk P4-07a (templates: item, npc, spawns, world, zone, stats, pet)

To be merged into [../DEVIATIONS.md](../DEVIATIONS.md) by the integrator. The code marks each one with a `Deviation:` comment.

## game server / static data templates

| Area | Java | C++ | Reason |
|---|---|---|---|
| `PetTemplate.getPetFunctions` | On the first call appends `PetFunction.CreateEmpty()` to the template's own list when no function is a player function (or creates a one-element list), caching the result in `hasPlayerFuncs`; unsynchronized, so concurrent first calls on the shared template can append twice or iterate a list being modified | Returns `std::vector<const PetFunction*>`: the bound functions followed by one shared immutable empty function under the same condition, computed on each call; the template is never modified. `getWarehouseFunction` reads the bound functions (the appended NONE function is never a warehouse, so the result is the same) | D6: obvious Java race on shared static data; templates are const after load. Test: `PetTemplateTest.ConcurrentPetFunctionReadsAreConsistent` |
| `ItemTemplate.afterUnmarshal` empty stats | `weaponStats`/`useLimits` without an element point at the shared statics `emptyWeaponStats`/`emptyUseLimits` | Each such template owns a default-constructed `WeaponStats`/`ItemUseLimits` (about 100k small objects) | The generated members are `std::unique_ptr`; the values are equal, only the identity differs (no Java code compares them by identity) |
| Exceptions of afterUnmarshal hooks | `RandomItem`/`ResultedItem` throw `IllegalArgumentException`, `TemporarySpawn` throws `NumberFormatException`/`ArrayIndexOutOfBoundsException` for a malformed expression, `WorldMapTemplate` throws `NullPointerException` without `flags`; JAXB aborts the load | `LoadContext::fail` throws `StaticDataException` with the Java message (the parse error text for `TemporarySpawn`) and the file/line/element location | The loader's error type; startup fails the same way (none of these occur in the data) |
| `ResultedItem.afterUnmarshal` item check | `(staticData != null ? staticData.itemData : DataManager.ITEM_DATA).getItemTemplate(itemId)` | Looks the item up among the XmlIDs of the current load (`LoadContext::findXmlId<ItemTemplate>`), no fallback to the published `ITEM_DATA` | Written before `ItemData::getItemTemplate` existed (header requests templates-b-1/items-1 added it and kept the hook: in a full load the XmlIDs are the same templates); decomposable items always load together with the items, and //reload is deferred (D3). Switch to `ItemData::getItemTemplate` with //reload |
