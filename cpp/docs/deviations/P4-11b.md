## Wave 5b-1, stage 1 close-out (m5b-plan.md E-01b, moved forward from stage 2)

**No new deviation; the same existing one shrinks again.** The DEVIATIONS.md row "Calls into classes without a C++ header" no longer covers
`AttackUtil.calculatePhysAttackResult`, the three `StatFunctions` reward functions or `PlayerRestrictions.canAttack`: B-01, B-02/B-03 and C-01
landed in this stage, five more stand-ins are deleted from `controllers/ControllerStandIns.{h,cpp}` (header request `m5b-3`), and
`CreatureController.cpp:356`, `NpcController.cpp:251,252,270` and `PlayerController.cpp:490` call the classes directly, as Java writes them
(CreatureController.java:323, NpcController.java:219/220/236, PlayerController.java:397). `tests/controllers/AttackSeamTest.cpp` and the rewritten
`tests/cm_ak/AttackPacketTest.cpp` assert what each callee answered, not merely that nothing threw.

Four stand-ins remain, each with a comment in `ControllerStandIns.h` naming the milestone that deletes it:
`attackUtilCalculateMagAttackResult` and `chargeSkillGetAndUse` (M5b-2, O-01/O-02), `playerRestrictionsCanUseSkill` (M5b-2) and
`playerTeamDistributionServiceDoReward` (P5-10), plus `followStartServiceNewFollowingToTargetCheckTask` from E-01a's list.

**`playerRestrictionsCanUseSkill` is kept deliberately although its header now exists.** `restrictions::PlayerRestrictions::canUseSkill` is an
`AION_PARTIAL` that refuses every skill until the skill engine lands (C-01, docs/deviations/P5-13.md). Pointing `PlayerController::useSkill` at it
would turn a throw into a silent "no" at a call site no test can reach yet (`CM_CASTSPELL` does not exist), which hides the gap instead of
recording it. The stand-in goes when M5b-2 makes the body real.

**One divergence is *not* closed and is not this chunk's**: `GeneralInstanceHandler::getExpMultiplier` (P5-13,
`instance/handlers/GeneralInstanceHandler.cpp:99-101`) is still `AION_UNPORTED`, and `StatFunctions::calculateExperienceReward` calls it. With the
AI registered, `NpcAI::ask(REWARD_AP_XP_DP_LOOT)` answers true, so **every npc death now reaches it**; the throw lands in the
`catch (const std::exception&)` of `NpcController::onDie` and becomes an ERROR line. `tests/controllers/AttackSeamTest.cpp` supplies the Java
answer (`1.25f` in the open world) through a test double, exactly as `tests/stats/CombatDamageTest.cpp` does, so the seam can be asserted before
the body exists.

## M5b-2, stage 1 part 1 (player-side lane, m5b2-plan.md P-04, first half)

**No new deviation; the DEVIATIONS.md row "Calls into classes without a C++ header" shrinks once more**: it no longer covers
`PlayerRestrictions` of P5-13. `standins::playerRestrictionsCanUseSkill` is deleted from `controllers/ControllerStandIns.{h,cpp}` (a signature
header request, in the lane report) and `PlayerController::useSkill` calls `restrictions::PlayerRestrictions::canUseSkill(player, *skill)` the
way Java writes it (PlayerController.java:474), through the `using` its `attackTarget` sibling already has. The reason M5b-1 kept the stand-in
is gone: `canUseSkill` is no `AION_PARTIAL` any more (P-01, docs/deviations/P5-13.md).

`chargeSkillGetAndUse` stays, as the plan says: it needs `SkillEngine::getChargeSkill` (S-01, part 2). Its comment in `ControllerStandIns.h`
now says why it is still unreachable - `CM_USE_CHARGE_SKILL` is not registered (P-03, docs/deviations/P5-16.md) and a charge skill must be
casting first.

**What the swap does not prove, stated so it is not mistaken for coverage.** `PlayerController::useSkill`'s first statement is
`SkillEngine::getSkillFor`, which is `AION_UNPORTED` until S-01, so no test can reach the `canUseSkill` line yet: replacing the call with
`if (false)` leaves every test green (watched; see the lane report). The restriction body itself is covered by `tests/instance/PlayerRestrictionsTest.cpp`
and the packet up to `getSkillFor` by `tests/cm_ak/CastSpellPacketTest.cpp`; the seam between them is the cast lane's first test when
`getSkillFor` lands.
