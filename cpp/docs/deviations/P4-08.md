## game server / skill and quest static data

| Area | Java | C++ | Reason |
|---|---|---|---|
| `MotionTime.afterUnmarshal` indexes | Builds `HashMap<WeaponTypeWrapper, HashMap<Integer, Times>>` per race and gender and a `HashMap<Integer, Times> robotTimes`, then sets the five bound lists to null | `std::map` indexes keyed by the normalized (main hand, off hand) `ItemGroup` pair of Java's `WeaponTypeWrapper` constructor (`MotionTime::weaponTypeWrapper`), with `const Times*` values into the bound lists, which stay | Stable template addresses (static-data.md §2.6); `WeaponTypeWrapper` (P5-02) has no C++ header yet. The maps are only looked up, never iterated, so the ordered map is not observable. Tests `MotionTimeHookTest.*`, `SkillShellsRealDataTest.MotionTimesBindWithHooks` |
| `MotionTime.getTimesFor(Player, id)` | Reads `player.isInRobotMode()` before the loop and again in every iteration | Reads the robot mode, race, gender and weapon types once and delegates to the C++-only `getTimesFor(inRobotMode, race, gender, mainHand, offHand, id)` | The lookup can be tested without a Player; the result differs only if the robot mode changes while the loop runs |
| `Effects` type sets | `EnumSet<EffectType>` fields; the type is resolved from `getClass().getSimpleName()` | `std::set<EffectType>` members (ordinal iteration order); the type is resolved from `javaClassName()` with the same `replace("Effect", "").toUpperCase()` rule | No reflection (static-data.md §2.2). All 169 concrete effect classes resolve: `EffectsHookTest.EveryEffectChoiceResolvesItsEffectType` |
| `Motion.afterUnmarshal`, `Times.afterUnmarshal` | `String.intern()` of the motion name and the weapon, only to save memory; `Times` throws `NullPointerException` for a missing `weapon` | `Motion`: no-op. `Times`: an empty weapon (absent; the census finds no present-empty value) fails the load with `LoadContext::fail` | `std::string` has no interning; the loader's error type with the file location, the load fails as in Java (P4-07a does the same for its hooks). Test `TimesHookTest.WeaponIsRequiredByTheHook` |
| `Effects.afterUnmarshal` without effects | An `<effects>` element without children leaves the list null, and the hook throws `NullPointerException` | `LoadContext::fail` with the Java exception name | Same failure with the loader's error type; no such element in the data |
| Lazily created lists: `Actions.getActions`, `ActionModifiers.getActionModifiers`, `QuestEvent.getIds`, `OnKillEvent.getMonsters` | The getter stores a new empty `ArrayList` into the template when nothing was bound, unsynchronized, and returns the live list | Returns the bound list or an empty one (a shared immutable vector for `getIds`); the template is never modified | D6: an unsynchronized write to shared static data; templates are const after load and no Java caller adds to the returned list. Tests `QuestEventTest.IdsAndMonsters`. One Java branch depends on the null: `OnKillEvent.operate` returns false for `monster == null`, but `XmlQuest.register` (and `XmlQuestData.getAlternativeNpcs`) call `getMonsters()` at QuestEngine load, so at run time Java always sees a non-null list and runs `complite.operate(env)`; the P5-06 port of `operate` must therefore not return early for an empty `monster` (no `on_kill_event` exists in quest_script_data today) |
| `Condition implements StatCondition` | `Condition` implements the `StatCondition` interface (`validate(Stat2, IStatFunction)`) | `Condition` declares the virtual `validate(Stat2&, IStatFunction&) const` itself and has no `StatCondition` base; no C++ header for `StatCondition` exists | `Condition` is the only implementor and no Java code holds a `StatCondition` (`Conditions.validate(Stat2, IStatFunction)` calls it through `Condition`); header request shells-3 |
