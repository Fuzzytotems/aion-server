## game-server / network (`network/**`, P4-15)

| Area | Java | C++ | Reason |
|---|---|---|---|
| Server packet serialization | `AionServerPacket.write` runs `writeImpl` lazily on the NIO dispatcher thread when the packet is written | `serialize` runs `writeImpl` eagerly on the sending thread into a thread-local scratch buffer (nested serializations get their own buffer); the connection queue holds the serialized bodies ordered by serialization sequence; `writeData` on the IO strand prepends the length and encrypts. A `writeImpl` exception reaches the sender instead of disconnecting the client | runtime-architecture.md §8 (eager packets, D1); the IO strand never touches game objects |
| Oversized server packets | Warned in `writeData` after writing | Warned in `sendPacket` after serializing (same message) | The size is known after serialization |
| Packet name echo for membership-10 accounts | Sent from `writeData` for every written packet except `SM_MESSAGE` | Sent from `sendPacket` after the packet was queued | runtime-architecture.md §8.6: the IO strand does not send packets |
| `SM_KEY` | Queued by `initialized()`; `writeImpl` enables the key while it is written on the dispatcher | Serialized for the connection in `initialized()` before IO starts (the key is created there); the first `encrypt` on the strand still only enables the crypt. Until P4-16 ports `SM_KEY.writeImpl`, the connection uses a private `SM_KEY` subclass with Java's one-line `writeImpl` | runtime-architecture.md §8.5; the key exchange must work before P4-16 |
| `ConnectionAliveChecker` creation | In the constructor | In `initialized()`; the scheduled task runs on its own copy of the `std::weak_ptr<AionConnection>` (the `task` member is initialized before the `aionConnection` member, so the task never reads that member) and does nothing once the connection is gone | `weak_from_this()` is empty during construction (runtime-architecture.md §11) |
| Packet flood filter map (`pffRequests`) | Created only with `PffConfig.PFF_MODE > 0` and a threshold map when the connection is created | Always created; `processData` checks `PFF_MODE > 0` (and a threshold for the opcode) for every packet | Frozen header layout (always-created member); only a config reload during a connection's lifetime behaves differently |
| `AionConnection.toString` | Plain field reads | Opens its own `TaskScope` for the field loads | Called from commons log statements outside any task |
| Client packet table | Reflective `PacketInfo` table built in the static initializer | Built on first use from `ClientPacketInfo.gen.inc` and the `AION_CLIENT_PACKET` registry; `setEntries` replaces the registry (startup, tests). A class without a registration (not ported yet) is logged once and the packet ignored | No reflection; partial port |
| Unknown opcode log | `String.format("...%n%s")` (platform line separator) | `\n` | Deterministic logs (as in commons) |
| LS/CS link packet execution | `ThreadPoolManager.execute(packet)`: unordered, concurrently | A per-link `runtime::SerialExecutor` on the instant pool runs the packets in receive order | runtime-architecture.md §1.4 |
| LS/CS link connect | `SocketChannel.open` + `Dispatcher.register` on the calling thread | `NioServer::openSocket` inside a `BlockingRegion`, then `registerConnection` (commons convention for outbound connections) | Asio NioServer |
| `NetFlusher` | Own daemon `java.util.Timer` thread; `RuntimeException`s printed to stderr | Fixed-rate task on the ThreadPoolManager scheduled pool; exceptions logged | Game code creates no threads |
| `CM_PTRANSFER_RESPONSE` wrong server id | Throws and catches an `Exception` to print its stack trace to stderr | Logs the exception with the class logger | No stderr stack traces |
| `CsClientPacket.clonePacket` | Shallow `Object.clone()` | Returns null (Java's `CloneNotSupportedException` result) | No polymorphic shallow copy; nothing calls it |
| `GameConnectionFactoryImpl.create` | `NetworkConfig.ENABLE_FLOOD_CONNECTIONS` switched on by a reload after the factory was created: NullPointerException | The flood check is skipped while the factory has no `FloodManager` | Java bug (NPE on the accept path) |
| `ConnectionFactory` | `GameConnectionFactoryImpl implements ConnectionFactory` | RefCounted factory plus `toConnectionFactory()` returning the commons `std::function` (it retains the factory) | commons `ConnectionFactory` is a `std::function` |
| `BannedMacManager` banned-until log | `Timestamp.toString()` (nanosecond fraction) | Same format with millisecond precision (the fraction without trailing zeros) | `Timestamp` has millisecond precision |
| Stand-ins for missing companions (temporary) | `ItemSlot`, `ItemGroup.getArmorType`, `PlumStatEnum`, `StatEnum.getItemStoneMask/getSign`, `ChatType.getId`, `ChatUtil.l10n`, `Race.getL10nId`, `AbyssRankEnum.getRankL10n`, `Race.getRaceId`, `PlayerClass.getClassId`, `Gender.getGenderId`, `BanAction.getId` | Private data tables in `network/detail/ItemData.h`, `network/detail/EnumIds.h`, `network/detail/SystemMessageL10n.h` and `SM_HDDBAN_CONTROL.cpp`, copied from the Java enums | The companion headers belong to P4-05/P4-07a/P4-13/P5-01 and do not exist yet; replace when they land |
| `GameServer.isShutdownScheduled/isShuttingDownSoon` | ShutdownHook state | Always false until P5-14 writes `GameServer.h` and the ShutdownHook (header request network-1 rejected) | The GameServer class belongs to P5-14; no shutdown can be scheduled before |
| LS/CS link send after a link drop (D6) | `LoginServer.authenticateClient/requestAuthReconnection/sendPacket` and `ChatServer.sendPlayer*` read `lsCon`/`csCon` in `isUp()` and again to send; `kickOnlineCharacters` reads `player.getClientConnection()` twice. A link drop (`disconnect()` nulls the field) or a logout between the reads throws a NullPointerException in the caller | The connection is read once (`upConnection()`, one `getClientConnection()`): the send goes to the connection that was checked, which ignores it once closed; `sendPacket` returns true as if the drop came after the send | Obvious Java race (design D6); a null `std::shared_ptr` dereference would crash the process. Tests: `LoginServerLinkTest.LinkDropWhileAPacketIsWritten`, `*.SendingRacesWithTheLinkDrop` |
| LS server packet serialization | `LsServerPacket.writeImpl` runs lazily on the NIO dispatcher in `writeData` with `guard` held (`SM_PTRANSFER_CONTROL` loads items from the database there, `SM_ACCOUNT_LIST`/`SM_LS_CONTROL` read game state) | `LoginServer` serializes every LS packet it sends on the sending thread (into a buffer of the link's write buffer size, the same overflow bound) and queues the bytes; `writeData` only copies them. A `writeImpl` exception reaches the sender instead of the dispatcher. Packets sent by the link itself (`SM_GS_AUTH`, `SM_LS_PONG`) stay lazy, they read no game state | runtime-architecture.md §1.1: IO threads frame and write serialized bytes and never block on the database while other senders wait on `guard`. Test: `LoginServerLinkTest.LinkDropWhileAPacketIsWritten` |
| `PvpInstanceScoreWriter.writeEmptyDataToBuffer` with more players than the table | `new byte[negative]`: NegativeArraySizeException | `IllegalArgumentException("Negative array size: n")`, as `PacketWriteHelper::skip` | The runtime has no NegativeArraySizeException type |
