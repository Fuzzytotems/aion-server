## M5b-2, stage 1 part 1 (player-side lane, m5b2-plan.md P-01)

**The M5b-1 partial is closed and no deviation replaces it.** `PlayerRestrictions::canUseSkill` is PlayerRestrictions.java:51-116 statement for
statement: the prison message first, then the target read, `checkFly || isAboutToDie || isDead`, the private-store message, the silent refusal
of a skill cast in progress (an item cast passes), `!canAttack() && !hasEvadeEffect`, the SILENCE and BIND arms, `isSkillDisabled`, the
transform arms with the FORM1 panel audit, and the resurrect-target check. The one shape worth a note is not a deviation: `isCasting()` and
`getCastingSkill()` read the field twice, as Java does (`// java-race`), and a cast that ends between the two reads dereferences a null
`Ptr`, which throws `NullPointerException` exactly where Java would. Every callee is ported; the body has no `AION_UNPORTED` and no
`AION_PARTIAL`.

This deletes the §B row `aion/gameserver/restrictions/PlayerRestrictions.cpp:60` of `tests/scenario/m5b_partial_allowlist.txt` (a P5-SC file,
requested in the lane report): the site no longer exists, so the row can only ever count 0, which §B asserts and which therefore stays green
while being meaningless.

Tests: `tests/instance/PlayerRestrictionsTest.cpp`, `CanUseSkillTest.*` (21 cases, each guard mutation-proven). **Not covered, and why**: the
SILENCE and BIND arms, because `EffectController::setAbnormal` - the only writer of the state they read - is still `AION_UNPORTED`
(m5b2-plan.md K-02); and the multicast exception inside `Player::isSkillDisabled`, which reads `ChainSkills` (`AION_UNPORTED`, S-06). The
`isActive()` guard around the transform arms is an equivalent mutant for every reachable state: `TransformModel::apply` with model 0 resets
`cantUseSkills` and the type together with the model, so an inactive transform never answers `cantUseSkills()` or `FORM1`.
