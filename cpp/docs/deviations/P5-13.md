## M5b-1 (player-side lane, m5b-plan.md C-01)

`restrictions/PlayerRestrictions` is a **new file**: before M5b-1 the whole `restrictions` package was its `fwd.h`. Ported M5b-1 subset:
`canAttack` and the private `checkFly` it calls. Tests: `tests/instance/PlayerRestrictionsTest.cpp`.

| Area | Java | C++ | Reason |
|---|---|---|---|
| `PlayerRestrictions.canUseSkill` | 65 lines of checks that end in `return true` for an unrestricted caster (PlayerRestrictions.java:51-116) | `AION_PARTIAL("PlayerRestrictions.canUseSkill refuses every skill: its checks need the skill engine (M5b-2, m5b-plan.md C-01)")` and `return false` | Every branch of the Java body reads the skill engine (`SkillTemplate::hasEvadeEffect`/`getType`/`hasResurrectEffect`, `Player::getCastingSkill`/`isSkillDisabled`, `EffectController::isAbnormalSet`), which is chunk P5-02 and milestone M5b-2. Refusing is the conservative one of Java's two answers and follows m5b-plan.md **D4**, where `GeneralNpcAI.chooseSkillAttack` is an `AION_PARTIAL` returning `false`. **There is no caller at M5b-1**: `PlayerController::useSkill` still calls `standins::playerRestrictionsCanUseSkill` (`ControllerStandIns.cpp:98`), which m5b-plan.md **E-01b** leaves standing until M5b-2, so the partial is reached by `PlayerRestrictionsTest.CanUseSkillIsThePartialOfM5b1` and by nothing else. M5b-2 replaces the body |
