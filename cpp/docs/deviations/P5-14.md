## game-server / startup (`src/main.cpp`)

| Area | Java | C++ | Reason |
|---|---|---|---|
| Handler engines at startup | `Stream.of(QuestEngine, AIEngine, InstanceEngine, ChatProcessor, ZoneService, GeoService).parallel().forEach(GameEngine::init)` | Only `ZoneService.init` and then `GeoService.init`, sequentially in the stream's source order | Milestone M4 excludes the handler engines (handlers-and-porting-plan.md §2.7: their registries are empty; `QuestEngine.init`, `AIEngine.init` and `ChatProcessor` are unported, P5-05/06/14). The two engines are independent in Java too (`ZoneService.init` only registers zone handler classes, `GeoService.init` creates material zones through the synchronized `createMaterialZoneTemplate`), so the order does not change the result |
| Startup after `World` | `GameTimeService`, `DropRegistrationService`, sieges, spawns, ... `initNioServer`, LS/CS connect | The startup ends after `World.getInstance()` with "M4 startup sequence complete", then the runtime and the database shut down in order and the process exits with 0 | The rest of `GameServer.main` is not ported yet (P5) |
| Task scopes of the startup steps | – (no epochs) | `DataManager`, `ZoneService.init`, `GeoService.init` and `World` each run in their own STARTUP `TaskScope` | The Reclaimer can free what one step unlinked before the next step starts (the geo load retires more than a million objects); no step keeps a borrow of another |
| Command line | `-D` properties are JVM system properties | `-Dkey=value` overrides layered over `mygs.properties` (unchanged from S0a); C++-only check options `--check-static-data`, `--check-id-factory`, `--check-output=<dir>`, `--check-geo-probes=<file>` | The M4 gate (`gs.m4.check_static_data`, `cmake/RunM4Check.cmake`) runs the normal startup path and writes report files for the independent oracles: the `StaticData` logger's "Loaded N ..." lines through an additional file sink, the geo statistics, the material zone names (a `GeoCallbacks` listener), 200 `getZ` probes, the zone names of every map instance, the unported trace and the load time and peak working set. Without these options the startup is unchanged |
| `DatabaseCleaningService.deletePlayersOnInactiveAccounts` | Called when `gameserver.cleaning.enable` | Called the same way, but the body is still `AION_UNPORTED` (P5-14) | The default configuration disables cleaning; an enabled cleaning stops the startup at the unported function |
