## M5j stage 4 CP5: SpawnsData.saveSpawn's write-back (2026-10-13, lane A, branch `lane-a/m5j-s4-cp5`; D14 = (a), faithful)

`SpawnsData::saveSpawn` now runs SpawnsData.java:204-274 in full. A //delete of a world spawn, and a //spawn with a respawn time, write
`./data/static_data/spawns/<Npcs|Gather|Instances|Rifts>/New/<world id>_<map name>.xml`, relative to the working directory, as Java does.

| Area | Java | C++ | Reason |
|---|---|---|---|
| Reading the spawn files | JAXB: `UnprocessedSpawns`, `Spawn`, `SpawnSpotTemplate`, `TemporarySpawn`, validated against spawns.xsd | The pugixml DOM of `xml::XmlDocument` read into plain records with the JAXB classes' attributes and defaults; no XSD validation (static-data.md §3.4) | The bound C++ templates are const and lack setters for every attribute |
| Writing | `JAXBUtil.serialize(data, schema)` (`JAXB_FORMATTED_OUTPUT`, UTF-8) | The JAXB RI's formatted form: `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>`, four-space indent, attributes in field order, the `beforeMarshal` omissions, floats as `Float.toString`, empty elements self-closed | |
| A New file's other `spawn_map` children (`base_spawn`, `rift_spawn`, ...) | marshalled back | not kept | saveSpawn writes only `<spawn>` groups, so a New file has no others |
| `addRegularSpawns(spawnMap)` with the JAXB objects | | The written text is bound as `UnprocessedSpawns`, and its map is passed; the bound holder is kept for the life of the process, because the spawn groups refer to its spawns | |
| `synchronized` | the method's monitor | a function-local immortal Monitor | |
| `Files.walkFileTree` | the folder's entries, depth first; an IOException is logged with `log.error("", e)` | `recursive_directory_iterator`; a filesystem_error is logged the same way | |

Tests (`tests/handlers_commands/C1/MonsterCommandsTest.cpp`, on a scratch working directory, never the Java tree):
- the guards touch no file;
- a //delete copies the group from the old template file, marks it custom and drops the spot;
- a move replaces the New file's spot, the template takes the position, and the custom group becomes the npc's world group;
- a new spawn creates its group;
- a missing folder gives "Could not save XML file!" and false;
- //delete's "Spawn removed permanently" answer.

The gates never reach the write, because their //spawn has no respawn time and their //delete removes single-time spawns.
`gs.scenario.m5j` (Z13) and `gs.scenario.gm` (X10) now check that no `New` folder appears under the Java tree's `data/static_data/spawns`.
No other gate sends //spawn, //delete, //spawnu or //fixpath.

Retest warning (for #124, "GM commands"): **`//spawn` with a respawn time and `//delete` of a world npc write
`game-server/data/static_data/spawns/<dir>/New/<map>.xml` in your Java tree (it shows in `git status`; delete the New folder to revert).**
