# P5-02a the cast machine: deviations

P5-02 was split into P5-02a (the cast state machine) and P5-02b (the effect machine) for M5b-2 (m5b2-plan.md D1). The rows of the shared
`P5-02.md` from waves 5a and 5b-1 stay there; this file holds the cast lane's rows from M5b-2 on.

## Wave 5b-2, stage 1 part 2 (cast lane, m5b2-plan.md S-01..S-08)

### Fixed in the fixer run (review finding: raw float-to-int casts)

`HpUseAction.getCost` (`(int) (valueWithDelta / 100f * maxHp)`), `HpUsePeriodicAction.act` and `MpUsePeriodicAction.act` (`(int) (max *
(value / 100f))`) were written as `static_cast<int32_t>` of a float, which is undefined behaviour out of the int range (MSVC answers
`INT_MIN`). They now go through the saturating `javaFloatToInt` that Skill.cpp and MotionData.cpp use (NaN 0, `Integer.MAX_VALUE` /
`MIN_VALUE` beyond the range, JLS 5.1.3). Observable: with `value="2000000000" ratio="true"` Java's cost is `Integer.MAX_VALUE`, which nobody can
pay, where the old cast charged `INT_MIN` - `reduceHp` then clamped the caster down to 1 HP and the effect ran on. Tests (both failed before the
fix): `SkillConditionsTest.ARatioCostBeyondTheIntRangeSaturatesLikeJavasCast`, `APeriodicRatioCostBeyondTheIntRangeSaturatesAndEndsTheEffect`.

### Not a deviation: the critical proc of a bow is a stagger

`SkillEngine.createCriticalProcEffect` comments `case BOW -> id = 8217; // stun` (SkillEngine.java:211), and M5b-1's rows in P5-02.md called
it the stun arm. Skill 8217 "Stunned" has a single effect, `<stagger duration1="2000" .../>` (skill_templates.xml), so the proc is a
**`StaggerEffect`**, not a `StunEffect`; 8218 (POLEARM, STAFF, GREATSWORD) is a `<stumble>`, a `StumbleEffect`. The port keeps Java's comment;
the test is `CriticalProcEffectTest.BowCreatesTheStagger`.

### Findings for other owners (no change made here)

- **Soul sickness does not go through `getSkillFor`.** m5b2-plan.md X10 and its mutation table assume that `SkillEngine.getSkillFor`'s PROVOKED
  bypass is what lets 8291 through; it is not: `PlayerController.updateSoulSickness` calls `SkillEngine.getSkill(player, 8291, deathCount,
  player)` (PlayerController.java:723-733), which never asks the skill list. For an unlearned PROVOKED skill, `getSkillFor` answers a
  `NullPointerException` from the Skill constructor (`effector.getSkillList().getSkillLevel(id)`, Skill.java:107), in Java and here. Test:
  `SkillCastTest.GetSkillForAsksTheSkillListExceptForAProvokedSkill`.
- **A static-initialization deadlock pattern in the test tree.** A test fixture that binds an NpcTemplate from XML in a `static inline` member
  initializer (`tests/controllers/AttackSeamTest.cpp` does, and so did this lane's first draft) runs the XML binder during static
  initialization; in `aion_gs_skills_tests` that hung the process before `main` (even `--gtest_list_tests` never returned). The cast lane's
  fixture binds its template on first use instead (`CastTest::monsterTemplate()`).
- **A stale comment in `ai/handler/SpawnEventHandler.cpp:23-24`** (P5-05) still says `SkillEngine::getSkill` is `AION_UNPORTED`; it is ported
  since part 2, and what keeps the post-spawn casts off the spawn path is only P5-02b's holdback of `getPostSpawnSkills`.
