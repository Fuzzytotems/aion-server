# Deviations of chunk P4-04 (geo engine)

To be merged into [../DEVIATIONS.md](../DEVIATIONS.md) by the integrator. The code marks each one with a `Deviation:` comment.

## game-server / geo engine (`geoEngine`, except `geoEngine/math`)

| Area | Java | C++ | Reason |
|---|---|---|---|
| Mesh collision trees | `GeoWorldLoader.load` preloads the BIH trees on the long-running pool after the maps are published; a collision check can meanwhile build the same tree lazily, since `Mesh.createCollisionData` is unsynchronized and `BIHTree.construct` sorts the mesh's triangles in place | `GeoWorldLoader::load` builds the tree of every mesh of the loaded maps on the ForkJoin pool before it returns; the lazy path stays for meshes outside the maps (`// java-race` on `Mesh::createCollisionData`) | Obvious race (D6, research/dao-geo.md): concurrent sorting while another thread traverses the triangles gives wrong collisions. Test `GeoWorldLoaderFilesTest.LoadsTerrainsMeshesAndPlacements` (every geometry of the map has its tree after `load`) |
| Terrain images | `loadTerrains` decodes the PNGs in a parallel stream and calls `setHeightmap`/`setMaterials` from those threads, so the size checks between a map's heightmap and materials read the other file's fields without synchronization | The images are decoded in parallel, then applied to the terrains on the calling thread in file name order | Obvious race (D6); the checks are symmetric, so the order does not change which images are accepted. Test `GeoWorldLoaderFilesTest.LoadsTerrainsMeshesAndPlacements` (a heightmap, a materials image and a heightmap shared by two maps) |
| `BoundingBox.containAABB` | Stores `min + max` into `center` and halves it in a second step | Computes the halved center first and stores it once | Obvious race (D6): the maps load in parallel and share meshes, so `Geometry.updateModelBound` of one thread can read a mesh bound another thread is recomputing and see the doubled center (a wrong world bound, chunk and zone name). Single-threaded results are identical (`BoundingBoxTest.ContainAabb`); the interleaving itself is not testable |
| `TempVars` after an exception | An exception between `TempVars.get()` and `release()` leaves the instance marked as used; after five such exceptions every geo call on that thread throws `ArrayIndexOutOfBoundsException` | `TempVars::ReleaseGuard` releases the instance when an exception leaves the scope (all Java `release()` calls stay where they are) | Java bug: e.g. `BIHNode.intersectWhere` throws `ArithmeticException` for a geometry with a singular world matrix (none in the data) while holding an instance. Tests `TempVarsTest.StackDiscipline` and `BoundingBoxTest.ContainAabb` (a failed `containAABB` leaves the stack usable) |
| `BIHNode.intersectWhere` traversal stack | Clears the thread-local `TempVars.bihStack` only on entry: an `onlyFirst` stop (every `canSee` and every first-hit query) or an exception leaves the pushed far-node entries in the `ThreadLocal` list until the thread's next BIH query | The stack is cleared before `release()` and by a scope guard on the exception path, so it is empty outside the call | The C++ entries hold `Ref<BIHNode>`, and runtime-architecture.md L15 allows no Ref in thread-local storage beyond a call (review of wave 3a-2). No observable behaviour change. Tests `BihTest.OnlyFirstStopsAtTheFirstCollision`, `BihTest.AnExceptionLeavesNoNodeInTheThreadLocalStack` |
| Game service lookups | `DespawnableNode.collideWith` calls `EventService` and `SiegeService`; `GeoWorldLoader.createZone` calls `ZoneName.createOrGet` and `ZoneService.createMaterialZoneTemplate` | `GeoCallbacks`: replaceable function pointers for the event theme id, the siege shield state and the material zone sink; without a callback the event theme and shield state come from `EventService`/`SiegeService` as in Java, and the material zone sink reaches `ZoneName::createOrGet` and `AION_UNPORTED` (`ZoneService.h`, P4-10, does not exist yet) | Handlers-and-porting-plan.md §2.6: geo can become a leaf library; the world and siege chunks register their bindings. Tests `DespawnableNodeTest.CollisionGates`, `GeoWorldLoaderFilesTest` |
| PNG decoding | `ImageIO.read` (any PNG); RGB samples stored as BGR, RGBA as ABGR | `utils::PngImage`, a self-written decoder; samples keep the PNG order; interlaced images with fewer than 8 bits per sample are rejected with `IOException`; chunk CRCs are not checked | No PNG library in the build (the plan's lodepng was not added: no new vcpkg packages). The loader accepts only one sample per pixel, and the data has 16-bit and 8-bit grayscale and one 8-bit palette image, none interlaced (`PngImageTest`) |
| Load errors | `GameServerError` (an `Error`) wraps `IOException`/`CloneNotSupportedException` of `loadMeshes` and every exception of `loadWorld`; a negative name length throws `NegativeArraySizeException` | `commons::utils::Exception` with the same message and the cause; a negative name length throws `IllegalArgumentException("NegativeArraySizeException: n")`; `CloneNotSupportedException` is `scene::CloneNotSupportedException` | CONVENTIONS: fatal startup errors are commons exceptions; `GameServerError.h` (P5-14) does not exist. Test `GeoWorldLoaderFilesTest.LoadErrors` |
| `Spatial.matches` | `Class.isInstance` (any subclass) and `String.matches` (java.util.regex); a null name never matches | The class filter is a `std::type_info*` tested with `dynamic_cast` for the scene classes and by exact type otherwise; the pattern is an ECMAScript `std::regex` over the whole name; an empty name (Java null) never matches | No reflection or java.util.regex; the Java code has no caller with a pattern (`Node::descendantMatches<T>` tests the class with the template argument) |
| Identity hash codes | `CollisionResult.hashCode`, `toString` and the index array records use `System.identityHashCode` of the geometry or array | A hash of the object address | Not reproducible; only used for hashing and debug output |
