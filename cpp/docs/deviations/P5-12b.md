## Wave 5a (player-events lane, m5a-plan.md E1-07)

Ported M5a subset: EventService (constructor, start, stop, validateConfiguredEventNames, checkActiveEvents, isInactiveEventForceType,
onTimeChanged, the six player/team/kill hooks, isAllEvents, collectActiveEvents, findOrCreateEvent, startOrStopEvents, collectQuestIds,
collectDropRules, isEventActive, isActiveEventQuest, getActiveEventConfigProperties, updateEventTheme), RiftService (initRiftLocations, initRifts
disabled branch, isValidId, isRift, isRiftOpened, updateSpawned, getDuration, getRiftLocation), RiftManager (addRiftSpawnTemplate,
addSpawnedRift, getSpawnedRifts, removeSpawnedRift), RiftInformer (all), VortexService (initVortexLocations, getLocationByRift,
getLocationByWorld), PanesterraService (getSiegeId, onEnterPanesterra for maps outside Panesterra), ConquerorAndProtectorService (init,
getCPInfoForCurrentMap x2, onEnterMap, onLeaveMap, onEnterZone and onLeaveZone guards, getOrRemoveCooldown, getCPTypeForCurrentMap),
WorldRaidService (initWorldRaidLocations, initWorldRaids disabled branch, getActiveWorldRaidLocations, isValidWorldRaidLocation,
isWorldRaidInProgress), BaseService.initBases, Event.isEventEffectForceType (reached from PlayerEffectController.addSavedEffect through
EventService.isInactiveEventForceType on every stored effect row of a loading character). RiftManager.addRiftSpawnTemplate is ported in full
instead of the planned `AION_PARTIAL`.
Tests: `tests/worldevents`.

| Area | Java | C++ | Reason |
|---|---|---|---|
| `EventService` collection fields | Initialized with `Collections.emptySet()`/`emptyList()` | The constructor creates empty shims | The singleton is created on first use, not during static initialization; every reader sees a collection as in Java |
| `EventService.getActiveEventConfigProperties` | The provider of `Config.load` | Ported, but not registered with `Config::setEventConfigPropertiesProvider` | `main.cpp` registers the `-D` overrides as that provider (plan E1-07 keeps it); events stay off in M5a (O-11) |
| `EventService.getActiveEventConfigProperties` sort | `Comparator.nullsFirst(Comparator.comparing(EventTemplate::getStartDate))` throws `NullPointerException` when an active event has no start date (`nullsFirst` null-checks the elements, not the extracted key) | Templates without a start date are ordered first, then by start date (stable) | An event without a start date is active (`isInEventPeriod`), so the Java code would fail instead of loading its properties; the port does what the comparator was meant to do. Off the M5a path (D1 disables every event); revisit with O-11 |
| `EventService.findOrCreateEvent` | `et.equals(event.getEventTemplate())` | Pointer identity | EventTemplate does not override `equals` |
| `RiftService.locations`, `WorldRaidService.raidLocationsById` | Alias the data holder's map or `Collections.emptyMap()` | A new shim filled with the data holder's entries (empty while disabled) | The frozen headers declare `Field<Ref<RcHashMap>>` |
| `RiftManager.getSpawnedRifts` | Returns the live `CopyOnWriteArrayList` or `Collections.emptyList()` | A snapshot vector | A COW list iterator is a snapshot as well |
| `ConquerorAndProtectorService.init` | `KILLS_DECREASE_INTERVAL * 60000` (int arithmetic) | Wrapping unsigned multiplication cast back to `int32_t` | Signed overflow is undefined in C++ (CONVENTIONS.md) |
| `RiftInformer` controller casts | `(RVController) rift.getController()` | `dynamic_cast`, `std::bad_cast` for another controller | Java throws ClassCastException |

### AION_PARTIAL / unported on purpose

- `BaseService` constructor: `AION_PARTIAL` (the BaseLocation subclasses have no bodies yet); it logs "Initializing bases..." and creates no base
  location, so `initBases` starts nothing.
- `EventService.startOrStopEvents` reaches `EventDAO.deleteOldBuffData` only when an event starts: `AION_UNPORTED` (events are O-11).
- Enabled branches outside M5a stay `AION_UNPORTED`: `RiftService.initRifts` (RiftSchedule), `WorldRaidService.initWorldRaids`,
  `VortexService.spawn`/`startInvasion`, `ConquerorAndProtectorService.onEnterZone` for an occupied Legion Dominion zone and the kills decrease
  (`addVictims`), `PanesterraService.onEnterPanesterra` on Panesterra maps.
