# P5-06b the quest handler base: deviations

P5-06 was split into P5-06a (the engine), P5-06b (the handler base) and P5-06c (the XML templates) for M5d (m5d-plan.md D1, item I-01). The
rows of the shared `P5-06.md` from wave 5a and M5b-3 stay there; this file holds the handler-base lane's rows from M5d on. No part may edit
`P5-06.md` (`chunks.py check-ownership` allows a chunk only its own `docs/deviations/<chunk>.md`), so a lane that closes or changes one of its
rows says so here and the integrator edits the shared row when it merges the lane.

Not asserted by a unit case, with the reason:

- `isAcceptableQuest`'s `minlevel_permitted == 99` arm and its class-reward clause (:477-481). Its only caller asks it after
  `checkStartConditions`, which refuses a level-99 quest, and the shipped data has one quest without rewards but with class rewards, 2991, at level
  99. The whole conjunction is proven by 1195 (no reward of any kind, not opened); a mutant that ignores the class clause is equivalent on the
  shipped data.
- `defaultCloseDialog`'s `DIALOG_FINISH` to the npc's AI (:524-525): the unit tests' npcs run AIEngine's substitute AI (the warn mode of
  `gameserver.dev.missing_ai_handlers`), which ignores it.
- `sendQuestStartDialog`'s `itemId != 0 && itemCount != 0` before `giveQuestItem` (:381): `giveQuestItem` checks the same itself (:629), so
  a mutant that weakens the outer check is equivalent.
- `isAcceptableQuest`'s bonus, quest-drop and extended-rewards clauses (:479), one at a time: the only follow-ups that pay nothing but quest
  drops, 1416 and 11041, are `minlevel_permitted` 99, which `checkStartConditions` refuses first, and no follow-up pays only a bonus or only
  extended rewards, so dropping one clause is equivalent on the shipped data.
- The resize in `treeifyBin` below 64 buckets, in the `HashSet(0)` model: across the 1,441 start npcs of `quest_script_data` (the largest set
  49 ids) no bucket reaches 9 ids, so no shipped set takes that path.
- The z window of `spawnInFront`'s `GeoService.getZ` (:1266): the unit tests load no geo data.
- Re-locking a quest the player already holds LOCKED in the two campaign starts (the `qs == null` of :1028 and :1100):
  `QuestService.addOrUpdateQuest` returns at once for an unchanged status (QuestService.java:457-458), so a mutant that drops the check is
  equivalent.
