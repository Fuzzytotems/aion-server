## Wave 5a, stage 2 (fixer run, world/controller/engine/service lane)

| Area | Java | C++ | Reason |

| `SummonedObject.setupStatContainers` | `setGameStats(new SummonedObjectGameStats(this))` | The same | **Resolves the `setupStatContainers` row of the stage-2 world-visibility section above** (header request hr-1, answered by P5-01 in the same wave): the `NpcGameStats` stand-in and its `TODO(header-request)` are gone, so all 2,060 house npcs plus every Kisk and GroupGate carry Java's stat container. Corrected in stage 3: that row is about the classes that use `SummonedObject`'s own `setupStatContainers` (`SummonedHouseNpc`, `Kisk`,
`GroupGate`). `Homing`, `Servant` and `Trap` **override** it and their overrides are still `AION_UNPORTED`, because Java installs
`HomingGameStats`, `ServantGameStats` and `TrapGameStats` and none of the three has a C++ header yet (P5-01). Constructing one therefore still
throws out of `postConstruct`. Substituting `SummonedObjectGameStats` would not be faithful: `HomingGameStats` and `ServantGameStats` derive it
but override `getStat`/`getMBoost` with their own rates, and `TrapGameStats` derives `NpcGameStats`, not `SummonedObjectGameStats`
(`TrapGameStats.java:14`). No M5a path creates a homing, servant or trap (they come from skill effects, M5b), so the three bodies stay unported
until P5-01 delivers the three stat containers.

No deviation is left in this chunk for the master name of `SummonedHouseNpc`, `Trap`, `Homing` and `Servant`: `Npc::getMasterName()` reports the
`Field<std::string>` value `""` as `std::nullopt`, so without those overrides `SummonedObject::getMasterName` would substitute the creator's name
where Java (whose field is the empty string, not null) returns `""`. The overrides are what keeps the port faithful; they are listed under header
request `objects-1` and stay until the field can be an optional.

Stage-3 fixer run: those four overrides now have a test of their own, `SummonedObjectsTest.TheFourSubclassOverridesKeepJavasEmptyMasterName`.
It builds a real `SummonedHouseNpc` from a `House` without an owner (`SummonedHouseNpc.java:19-20`) and a `Homing`, `Servant` and `Trap` through
subclasses that replace only their `AION_UNPORTED` `setupStatContainers` with the closest base Java derives the missing stat container from
(`SummonedObjectGameStats` for homing and servant, `NpcGameStats` for the trap, `TrapGameStats.java:14`), and asserts for each that
`getMasterName()` is `""` while `SummonedObject::getMasterName()` would answer the creator's name. Before it, the file only set `""` on a
`TestSummonedObject` that has no override and re-stated in its own expectation what the overrides do, so rewriting any of the four to call the
base kept every test green.
