## game-server / item model (P4-13, `model/items`, `model/trade`, `model/broker`, `model/drop`, `model/enchants`)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `ItemStorage` iteration (`getItems`, `getItemsById`, `getFirstItemById`, `getSlotIdByItemId`; so `Storage.decreaseByItemId` and `getFirstItemByItemId`) | `ConcurrentHashMap<Integer, Item>` bin order: which of several stacks of an item id is found first or decreased first follows the object ids' hash bins and the table size | The runtime `ConcurrentHashMap` shim's stripe and bucket order | Hash iteration order is unspecified in Java too (CONVENTIONS.md); counts and results are the same, only the choice among equal stacks may differ |
| `ManaStone.getModifiers` | The template's modifier list itself, `null` for a stone template without modifiers | A list of the template's modifiers (`const StatFunction*`), empty without modifiers | The frozen member is an `ArrayList`; the item equipment listener (P5-01) tests the list for emptiness where Java tests for `null` |
| `EnchantEffect.getItemSlot` of an effect without `PHYSICAL_ATTACK`/`MAGICAL_ATTACK` stats | `null` | `MAIN_HAND` | The frozen member is a plain `ItemSlot`; `CreatureGameStats` reads it only for attack stats, only the `//stat` admin command prints it for other effects |
| `Drop.afterUnmarshal` validation | `IllegalArgumentException`, which fails the unmarshalling | `LoadContext::fail`: `StaticDataException` with the same message and the XML location; the public constructor still throws `IllegalArgumentException` | The binder contract for hook errors (static-data.md); same message |
| `DropGroup.tryAddDropItems` candidate order | `new HashSet<>(drops)` of identity-hashed `Drop`s: an arbitrary order that changes between runs | The drops in XML order | Deterministic; the nearest-chance rule and the random choice among ties (`Rnd.get`) are unchanged |
| `NpcEquippedGear` initialization | Lazily in the first `getItemsMask()`/`iterator()` call (synchronized) | Once after IDREF resolution while the static data loads (`init(LoadContext&)`), so an equipment item without an equipment slot fails the load instead of the first use | static-data.md §2.4 (the binder cannot resolve the item IDREFs earlier); the real npc templates have no such item (scan of the 160,491 equipment entries) |
| `NpcEquippedGear.init` publication | Publishes the empty `TreeMap` first, then fills it and ORs `mask`; `getItemsMask()`/`iterator()` test `items == null` outside the monitor, so a reader can get a partial mask or map. Runtime gear (`Npc.overrideEquipmentList`, e.g. CustomInstanceBossAI) is initialized lazily by `SM_NPC_INFO` on the sending threads. An exception in the loop leaves the partial map published | Builds the map and the mask locally, stores the mask, then publishes the map last; an exception publishes nothing (the next call throws again) | Obvious race (D6, review of wave 3a-2). Test `NpcEquippedGearTest.AReaderThatSeesTheItemsSeesTheWholeMask` (a reader at every store of `init`) |
| `GodStone.tryActivate` cooldown | `now < cooldownExpireTimeMillis.get()` then `set(now + cooldown)`: two concurrent hits of the weapon holder (a skill and an auto attack on different tasks) both pass the cooldown and both roll | A compare-and-set loop on the `AtomicLong`: one hit stores the new expiry and rolls, the other sees it and returns false | Obvious race (D6, review of wave 3a-2) defeating `GODSTONE_EVALUATION_COOLDOWN_MILLIS`. Test `ItemStonesTest.GodStoneCooldownLetsOnlyOneOfTwoConcurrentHitsRoll` (a second hit between the read and the store) |
| `BrokerPlayerCache.removeFromCache` | `stream().filter(...).toList()`: an unmodifiable list | A new modifiable `RcArrayList` | No shim for unmodifiable lists; no caller modifies the cached list |
| `IdianStone`'s anonymous `ActionObserver` | Captures its `IdianStone` (`this$0`) | A non-retaining `IdianStone* const` (fieldmap.toml `[captures]`, header request items-7), read through `stone()`, which terminates checked builds (C4) when the stone's Item was destroyed while the observer is still referenced | `onUnEquip` removes the observer before every replacement of the stone (PolishAction, polish charge 0) and `LogoutBreakers` cuts it at logout; the check catches an item destroyed without unequipping (a replaced stone cannot be detected: parts have no liveness cookie and a destructor may not reach the observer, C8) |
