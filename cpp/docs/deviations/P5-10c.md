# P5-10c deviations (alliances, M5g lane B, 2026-10-05)

The alliance model, service, events and the two alliance packets (m5g-plan.md AL-01..AL-04, §16). Every body follows the Java statement for
statement; the rows below are what C++ does differently and why.

| Area | Java | C++ | Reason |
|---|---|---|---|
| The four alliance groups at disband | `PlayerAlliance.groups` and each `PlayerAllianceGroup.alliance` reference each other; the garbage collector reclaims both | `PlayerAllianceService::disband` calls `PlayerAlliance::releaseGroups()` after the `AllianceDisbandEvent` removed every member | cycles.toml `PlayerAlliance.groups` cpp-breaker (the class comment of PlayerAllianceGroup.h); proven by `AllianceLifecycleTest.ALeaveFromTwoDisbandsAndReleasesTheGroups` and gs.scenario.m5g_alliance's `PlayerAllianceGroup` live 0 |
| Team lock classes | one `ReentrantLock` per team | `GeneralTeam` takes a per-kind lock class (`PlayerGroup::teamLock`, `PlayerAlliance::teamLock`, `PlayerAllianceGroup::teamLock`, `League::teamLock`) | header request m5g-1, **pending the owner's approval**: the alliance events lock the alliance's groups under the alliance's own lock, which one shared class reports as `SAME_CLASS_NESTING` (m5g-plan.md §16.2) |
| `PlayerAllianceInvite.collectPlayersToAdd` | a `List<Player>` | `std::vector<Ref<Player>>`: a player removed from his group is no team's member until he is added again | the list holds the players across the group removals |
| `List.remove(invited)` | the first element `equals` the invited player | the first element with `equals` (object ids, AionObject.java:52-64) | Java |
| Events | `new XEvent(...)` passed to `onEvent` | stack objects passed by reference (K5); `PlayerAllianceInvite` is RefCounted (K4, held by the ResponseRequester) | as the group events (P5-10b) |
| `OfflinePlayerAllianceChecker` | one instance scheduled at a fixed rate | a new instance per run (no state) | the captureless periodic task form, as the parties' checker (P5-10b) |
| D4's six event-side league calls and `disband`'s two | `alliance → league` under the alliance lock | the same order, inside a `LockdepSuppression` with the `// java-race` and `// lockdep` markers | m5g-plan.md D4(c); reached only by an alliance in a league |

### AION_UNPORTED on purpose

- The vortex arms (`VortexService.removeDefenderPlayer` in `removePlayer` / `banPlayer`, `removeInvaderPlayer` in the offline checker): the
  vortex is M5i's (m5g-plan.md O-04); only vortex alliances (`ALLIANCE_DEFENCE` / `ALLIANCE_OFFENCE`) reach them.
- `disband`'s two `league.onEvent(new LeagueLeftEvent(league, alliance))`: the league events are the league lane's (LG-03); only an alliance
  in a league reaches them.
