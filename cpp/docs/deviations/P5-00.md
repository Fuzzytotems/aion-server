# P5-00 login slice: deviations

## Wave 5a (slice lane, m5a-plan.md S-01..S-10)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `PlayerService.getPlayer` after `accountWarehouse.setOwner(player)` | No cleanup: an exception leaves the half-loaded Player to the garbage collector | A `runtime::finally` guard runs `LogoutBreakers::run(player)` when a load below throws; it is dismissed when getPlayer returns | The account warehouse retains the Player through its actor (m5a-plan.md S-05, LogoutBreakers.h "Callers") |
| `PlayerEnterWorldService.enterWorld(client, objectId)` after `getPlayer` | Only the `catch (Throwable)` branch cleans up (`controller.delete()`) | A `runtime::finally` guard runs `LogoutBreakers::run(player)` unless `enterWorld(client, player)` completed: the multi-client reject, the duplicate enter (which sends no packet) and the catch | Same reason; without it every rejected enter would keep a Player and its storages alive |
| `CM_CREATE_CHARACTER` on a database error | The unused `PlayerAccountData` and the transient `Player` are collected | The account data is a part of the account: unless it went into the account it is handed to `Reclaimer::retirePart`, so it outlives the transient Player that holds a `Ref` to it (C5) | A part destroyed while a Ref holds it is a checked-build error and a dangling reference in release builds |
| `CM_CHARACTER_PASSKEY` type 3 without a preceding enter or delete request | `CharacterPasskey.connectType` is `null`: neither branch runs | The generated enum field defaults to `ENTER`, so the port calls `PlayerEnterWorldService.enterWorld(client, 0)`, which answers `SM_ENTER_WORLD_CHECK(CONNECTION_ERROR)` | The frozen `CharacterPasskey` header stores the enum without `std::optional` (P4-12); only reachable with `gameserver.security.passkey.enable=true` (M5a: false) |
| `CM_MAC_ADDRESS.fixHddSerial` of text with unpaired surrogates | `readS` keeps the surrogate, `getBytes(UTF_16LE)` replaces it with the bytes of U+FFFD | `readS` already replaced it with U+FFFD, which writes the same bytes | Commons `readS` (documented in StringUtils.h); the hex dump is identical |
| `PlayerEnterWorldService.sendMacroList(client, player)` | Uses `PacketSendUtility.sendPacket(player, ...)`, the `client` parameter is unused | Same, with an explicit `static_cast<void>(client)` | The declaration is frozen (S0c) |
| `AccountService.removeDeletedCharacters` ratio branch | `GameServer.updateRatio(race, -1)` | `controllers::standins::gameServerUpdateRatio` (P4-11b stand-in) until `GameServer.h` exists (stage 2, S-12/F-01a) | `gameserver.character.ratio_limitation.enable` is false, so the branch is unreachable at M5a |
| `PlayerService` test seams | – | C++-only `setPlayerFactoryForTests` (how `getPlayer`/`newPlayer` create the Player), `setLoadHookForTests` (called after the account warehouse took the player as its actor) and `setStoreNewPlayerHookForTests` (called by `storeNewPlayer` after `PlayerDAO.saveNewPlayer` and before `PlayerAppearanceDAO.store`; a false makes `storeNewPlayer` return false) | The destroy-observer and breaker tests of S-10 need a Player with stat container doubles and an injected load failure (like `PetList::setPlayerPetsLoaderForTests`). The store hook replaces a `RENAME TABLE player_appearance` in the test: renaming a table under the live connection pool blocks on its open handles, which made the S-10 case (d) unreliable, and it mutates the shared `aion_cpp_test` schema. The hook injects exactly the state the rename produced (the players row written, nothing else), which is what Java leaves behind because `storeNewPlayer` is not transactional |
| Account warehouse actor of a rejected enter | The account warehouse's actor is left pointing at the rejected player (wrong, but non-null) | The breakers (L3) null the shared actor, so `PlayerService::restoreAccountWarehouseActor` puts the previous actor back unless it was the dropped player itself. Both S-05 guards remember the actor before `getPlayer` | The account warehouse is a part of the **Account**, shared by every Player of it. A second connection of the same account whose enter is rejected (multi-clienting, a DAO exception, the duplicate enter) reaches `getPlayer` first, which makes the rejected character the actor; without the restore the character that is actually online on the other connection would be left with a null actor - a null dereference where Java only misdirects a packet. A second `CM_ENTER_WORLD` on **one** connection cannot do it: `setActivePlayer` moves the connection to IN_GAME and CM_ENTER_WORLD is only valid in AUTHED. Test: `LoginSliceDatabaseFlowTest.AnEnterRejectedOnASecondConnectionKeepsTheAccountWarehouseActorOfTheOnlineCharacter` |

Kept Java races (`// java-race`): `CM_QUIT` calls `PlayerLeaveWorldService.leaveWorld` without synchronizing with `AionConnection.safeLogout`,
so a shutdown during `CM_QUIT` can run the logout twice (m5a-plan.md §7).

## M5c stage 0 (prereqs lane, m5c-plan.md M-02)

Both `PlayerService::getOrLoadPlayerCommonData` overloads are ported (PlayerService.java:235-247): the World's player first (by id or by
name), else `PlayerDAO.loadPlayerCommonData` / `loadPlayerCommonDataByName`. **No behavioural deviation.** Already-ported callers now run
further (m5c-plan.md W-37): `FriendListDAO.cpp:51` loads the friends at enter world instead of catching the `UnportedException` and leaving the
list empty, and `LegionService.cpp:203, 222` and `SM_GM_SHOW_LEGION_MEMBERLIST.cpp:22` no longer throw. Tests:
`tests/login_slice/PlayerServiceTest.cpp` (`GetOrLoadPlayerCommonDataAsksTheWorldFirstThenTheDatabase`, against the test database: a second
row under the in-world player's name proves the name overload asks the World first). The `AION_PARTIAL` at `PlayerService.cpp:268` did not
move, so no scenario allow-list row changed (I-04).
