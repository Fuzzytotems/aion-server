### Not a deviation

- **`removeByDispelEffect` spends its `count` on every match.** Java decrements `count` for every effect that passes the type, slot and level
  filters, also one whose power the dispel only weakened (EffectController.java:474-477), and so does the port; with a small count (the
  `DispelEffect` counts) a weakened first match leaves the next one alone. The part-2 review suspected a decrement on removal only; it is not
  there, and `EffectControllerRulesTest.RemoveByDispelEffectSkipsRemoveShockAndSpendsItsCountOnEveryMatch` fails if one is introduced. The
  fixes after that review added tests only; no production file of this chunk changed.
- **The order of `successEffects`.** Java's `ConcurrentHashMap<Integer, EffectTemplate>` iterates positions 1..4 in ascending order (one
  16-bin table; `spread(k) & 15 == k`). The C++ shim stripes by a murmur hash, so every loop Java writes over `successEffects.values()`
  iterates `javaOrderedValues(...)`, a snapshot sorted by position (Effect.cpp). A mutation that iterates the template list instead fails
  `EffectLifecycleTest.TheDurationIsTheFirstPositiveDurationInPositionOrderAndTheEndTaskFiresThen`.
- **The effect maps.** Java's `abnormalEffectMap` and `passiveEffectMap` are `LinkedHashMap`s (EffectController.java:27-28), as are the
  C++ shims, so dispel counts and icon packets see Java's insertion order. The initial `Collections.emptyMap()` of `passiveEffectMap` is
  a null field (EffectController.h's class comment).
- **The races Java writes.** `Effect.setAbnormal`, `EffectController.setAbnormal` / `unsetAbnormal` (`abnormals |= id` on a plain int) and
  `Effect.setDesignatedDispelEffect` (a plain check-then-set) keep Java's unsynchronized read-modify-write; each carries a `java-race` comment.
- **`Math.toRadians`** in `NpcSkillTemplateEntry`'s spawn position is `angdeg * 0.017453292519943295`, the JDK 9+ constant, so the
  rounding is Java's.
- **`Effect.endEffect` resets `designatedDispelEffect`** after `clearEffect`. That is the C++ breaker of cycles.toml
  "Effect.designatedDispelEffect" (a dispeller and its target would otherwise retain each other), not a behaviour change: the only readers of
  the field are the `EffectController` maps the ended effect has just left.
