# P5-06 quest engine: deviations

## Wave 5a (world-engines lane, m5a-plan.md W-02)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `QuestEngine.init`, quest handlers | `ScriptManager` compiles `data/handlers/quest` and `QuestHandlerLoader` adds each handler | The quest handler registry (`AION_QUEST_HANDLER` markers) creates the handlers; an entry whose handler reports another quest id than its marker throws IllegalStateException | Handlers are compiled in (QuestEngine.h) |
| `QuestEngine.init`, XML quests | `xmlQuest.register(this)` for every `DataManager.XML_QUESTS` quest | `AION_PARTIAL` when XML quests exist: none is registered (the XML quest handlers are wave 5b) | M5a runs without quests (m5a-plan.md W-02, D3) |
| `QuestEngine.init`, `gameserver.analysis.quest_handlers` | `QuestSpawnAnalyzer.run` on the long-running pool | `AION_PARTIAL` (the analyzer is not ported) | Not on the M5a path |
| `QuestEngine.init`, `drop.setQuestId(data.getId())` | Sets the quest id on the published template | Read only: the holder sets it while loading (docs/deviations/P4-07b.md) | Templates are const |
| `QuestEngine.init`, `<inventory_item>` without an item id | `questUpdateItems.add(null)` | Skipped | The C++ list holds ints; no item id equals null, so `onItemGet`/`onItemRemoved` behave the same |
| `QuestEngine.addQuestHandler`, duplicate quest id | The duplicate handler is dropped for the garbage collector | Kept alive (never registered) | Quest handlers are Immortal (RT-11) |
| `QuestService.getQuestDrop(npcId)` | The live list (or an empty list) | A snapshot | Collection returns (hub-headers.md §7.1) |

**Closed after the review (2026-09-24), outside this lane's files:** the row "`QuestEngine.init`, `drop.setQuestId(data.getId())` … the holder
sets it while loading" above described code that did not exist: nothing called `QuestDrop::setQuestId`, so every `<quest_drop>` of the static
data kept `questId` null and `isQuestDrop` threw Java's NullPointerException for it (Java unboxes `drop.getQuestId()`) — with `registerDrop`
ported, on every kill of an npc that has a quest drop (20 item ids on Poeta, e.g. 210668 *pinkbeak airon*), and `onDie`'s catch logged one
ERROR per kill. `QuestsData::afterUnmarshal` (P4-09) now sets it on every `<quest_drop>` of every quest before the holder is published — the
design `DEVIATIONS.md` "static data templates" row `QuestDrop.questId` describes (P4-07b.md is merged there) — and `QuestEngine::init` reads it
as its comment says. `QuestDropTest`'s fixture no longer sets the ids itself; `QuestDropTest.TheHolderGivesEveryQuestDropItsQuestIdAndInitRegistersItForTheKill`
binds the shipped rows through the holder, runs `QuestEngine::init` and kills 210668 with a character without quest 1108 (no drop, no
exception); removing the holder's assignment fails it and every case that reaches `isQuestDrop`.
`isQuestDrop`'s `ALLIANCE`-target and `MENTE` arms answer false for a solo player: `QuestDropTest.AnAllianceQuestDropsNothingForAPlayerOutsideAnAlliance`
(quest 30408), `AMenteeQuestDropsNothingForAPlayerOutsideAGroup` (quest 37001); the in-team halves need a group or an alliance (M5g).
