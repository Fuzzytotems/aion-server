## M5b-1, stage 2 (loot-partial lane, m5b-plan.md D5 / O-05, m5b-client-session.md S-1)

The first real-client session against the C++ server (2026-09-22, five kills) logged one ERROR per kill,
`onDie() exception for Npc [...]: ...DropRegistrationService::registerDrop ... is not ported yet`. `NpcController::onDie` reaches `registerDrop`
through `doReward` inside a `try` that only logs (`NpcController.cpp:172-181`, Java NpcController.java:146-155), so the kill completed and the
experience was kept — but `InstanceHandler::onDie` and the `DIED` AI event were skipped on every kill, and the gate's "no ERROR line" bar (§6.3
Q1) could not be met. `registerDrop` was the **only** `AION_UNPORTED` site the whole session reached (`server_warnings.log`: one
"AION_UNPORTED reached" line, for this body).

**What the skipped statements leave behind, and why the rest of the death path is safe.** `currentDropMap` and `dropRegistrationMap` stay empty,
so `NpcController::petLoot` and `findPetForLooting` — which run **after** the `try` of `onDie`, unguarded (`NpcController.cpp:196-230`, Java
NpcController.java:172-184) — find no `DropNpc` and return, and `DropService::unregisterDrop` on the despawn path removes nothing. No `DropNpc`
is created at M5b-1 at all, which is why `CheckOutput::zeroLiveClasses()`'s `DropNpc` row is a guard rather than an assertion until M5b-3.
