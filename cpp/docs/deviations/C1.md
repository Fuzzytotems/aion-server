### Proposed corrections (Java bugs, kept)

- **//delskill 0** (DelSkill.java:79-86): skill ID 0 skips the presence check, `getSkillEntry(0)` is null and `isStigmaSkill()` throws; the
  GM reads "<Error while executing command>". The fix: `if (skillId == 0 || !player.getSkillList().isSkillPresent(skillId))`. Pinned by
  `CharacterCommandsTest.AddSkillAndDelSkillRefusals`.
- **//state remove -1** (State.java:24 and :63-66): the syntax says "Use -1 to remove all states", but -1 fails the range check and the GM
  reads "Out of range state ID.". The fix: accept -1 as "all" (`stateId = 0xFFFF`) before the check, or drop the sentence. Pinned by
  `CharacterCommandsTest.StateSetsAddsAndRemoves`.

### Commands that reach unported bodies (AION_UNPORTED)

None of the commands of this section calls an unported body on the paths the tests run. //set's `ap` arm calls

`TownService.getTownResidence` -> `Player.getActiveHouse` -> `HousingService`, which needs the database (HousesDAO); the unit test stops there
(the full listing is the M5i gate's).

### Proposed corrections (part 2; Java bugs, kept)

- **//damage n with n <= 100 is a percentage** (Damage.java:79-80): `if (dmg <= 100) isPercent = true;` turns "//damage 50" into 50% of the
  max HP, while the syntax promises `<dmg | dmg%>`. The fix: drop the two lines (the `%` arm already sets isPercent). Pinned by
  `MonsterCommandsTest.DamageAPercentageOfTheHp`.
- **//useskill me|self|target without a skill ID** (UseSkill.java:47): `params[i++]` throws ArrayIndexOutOfBoundsException and the GM reads
  "<Error while executing command>". The fix: `if (params.length <= i) { sendInfo(admin); return; }`. Pinned by
  `MonsterCommandsTest.UseSkillRefusals`.
- **//ai event2 with the object ID of a non-creature** (Ai.java:105): `(Creature) World.findVisibleObject(...)` throws ClassCastException
  (C++ throws it explicitly). The fix: `instanceof Creature` and the "Please provide a valid creature object ID" answer.

## Structural parity of the command files (H-03, 2026-10-07, lane A, branch `lane-a/m5j-stage0-gate`)

`tools/parity` reads chat commands now (its README, "the chat command spellings"): the region of a command `.cpp` starts after its
`AION_*_COMMAND(X);` marker, Java text blocks and C++ adjacent literals are compared as values, and the per-line waiver of
handlers-and-porting-plan.md §3.1 item 2 exists in two forms, `// parity: <reason>` (the line is not compared) and `// parity= <Java>`
(the line is compared as that Java, read with the Java rules). All 41 ported command files (`admincommands`, `playercommands`,
`consolecommands`; C1 and C2) are at parity:

```
python tools/parity/parity.py tree --java-dir ../game-server/data/handlers --cpp-dir game-server/handlers/aion/gameserver/handlers --only <the 41>
parity: 41 pairs compared, 0 with mismatches, 0 Java files without C++
```

Every waiver was added as a comment; the code of the 41 files is unchanged except three behaviour-neutral respellings that bring the
operand order and form to the Java's (`Announce.cpp`: `allowedRace == std::nullopt`; `Kick.cpp`: `"ALL" == params[0]`; `Movie.cpp`: the
explicit ArrayIndexOutOfBoundsException check before `params[isCutsceneMovie ? 1 : 0]`, the same exception). The triage found no real
divergence. One edge, noted for the owner, not a proposal: //enemy's local `equalsIgnoreCase` (Enemy.cpp) folds ASCII only, while Java's
`String.equalsIgnoreCase` also folds by Unicode case mapping (so `npcſ`, U+017F, matches `npcs` in Java only).
