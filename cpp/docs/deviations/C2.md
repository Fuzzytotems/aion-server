# C2 system and console commands: deviations

## M5j stage 0 (lane A, branch `lane-a/gm-commands`)

//stat and //removecd (`admincommands/`) and the console commands ///levelup, ///leveldown and ///clearusercoolt (`consolecommands/`), ported statement for statement and
registered with `AION_ADMIN_COMMAND` / `AION_CONSOLE_COMMAND`. Tests: `tests/handlers_commands/C1/CharacterCommandsTest.cpp` (the command
library's one test directory).

| Area | Java | C++ | Reason |
|---|---|---|---|
| `Stat.CommandStatFunction` (a package-private nested class; Speed imports it) | `new CommandStatFunction(stat, value)` | `Stat::CommandStatFunction`, created as `RcStatFunction<Stat::CommandStatFunction>::create(stat, value)` | The run-time StatFunction lifetime of StatFunction.h. The `apply` parameter is `stat2` (Java `stat`), which would hide `StatFunction::stat` |
| `Stat.CommandStatOwner` (a record, one per StatEnum constant in a static EnumMap via `computeIfAbsent`) | created on first use, `forEach` visits the created ones | the owners of all constants are created together on first use (a function-local static), immortal; `forEach` visits all of them | Ending an owner that never added a function removes nothing and calls no `onStatsChange` (CreatureGameStats.endEffect), so visiting the unused ones is invisible. No lock is needed after the one-time initialization (Java's unsynchronized EnumMap is a race) |
| `StatFunctionInfo` (a record grouped with `groupingBy(f -> f, LinkedHashMap::new, counting())`) | record equality; `owner.equals` | a struct with `operator==` (the owners compared as CreatureGameStats' `ownersEqual`: identity, AionObject by object id); a vector of (info, count) in first-seen order | Same groups, same order |
| `StatFunctionInfo.type`: `getClass().getSimpleName()` of the (proxied) function | the subclass's name | `statFunctionClassName`: `RcStatFunction<T>` is reported as `T` | Java creates the subclass itself (e.g. `StatAddFunction`); C++ wraps it for the reference count |
| `StatFunctionInfo.toString`: `enchantEffect.getItemSlot() != null` | null for an enchant effect without attack stats | `EnchantEffect` stores MAIN_HAND there (P4-13), so such an owner prints " (MAIN_HAND)" | Inherited from the EnchantEffect port: the null is not representable. A //stat listing of an armor enchant shows the slot where Java shows nothing |
| //stat `abs`: `template.getModifiers().forEach(m -> applyStatFunction(creature, m))` | the static modifiers | the same `const StatFunction` objects (immortal static data) | |
| ///levelup, ///leveldown | `GSConfig.PLAYER_MAX_LEVEL` | `GSConfig::PLAYER_MAX_LEVEL.load()` | |
| //removecd: the cooldown maps' `entrySet().stream()` / `keySet().stream()` | Java's iteration order of the maps | `snapshot()` order of the C++ maps; the dummy item cooldowns go into SM_ITEM_COOLDOWN's `std::unordered_map` as at login (PlayerEnterWorldService) | The order of the entries inside the cooldown packets; the client reads them by ID |
| //removecd `removeItemCooldowns`: `new ItemCooldown(reuseTime, 0)` for the packet | garbage-collected | `ItemCooldown::create`, the Refs kept until the packet is written | Lifetime |
