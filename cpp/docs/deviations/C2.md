## C2 cp4: //configure and the P4-01 describe/field-name change (lane A, `lane-a/cmd-c2-cp4`, 2026-10-18; design approved 2026-10-18)

Java's //configure reads and writes the config classes' static fields by reflection. The C++ port names each bind instead:
`AION_BIND` / `AION_BIND_PATTERN` expand to `ConfigurableProcessor::bindNamed` / `bindPatternNamed` with `#FIELD` and the game server's
value formatter (`configs/detail/JavaString.h`); commons' DatabaseConfig and CommonsConfig call `bindNamed` with commons' `BasicJavaString`
(the formatter is a template parameter, so commons does not depend on game-server types). `ConfigurableProcessor::describe(binder)` runs a
bind function in introspection mode (no property read, no field changed) and returns one `FieldInfo` per bind: field name, key, default,
pattern flag, `toJavaString`, `set`, `setMap`. Commit A dumped every bind from the source (`tools/porting/config_bind_dump.py`,
`tests/configs/config_binds.golden.txt`, 448 rows of 36 classes) before any hub edit; `ConfigDescribeTest` proves describe() yields the same
rows, so naming the binds changed no key, default or order.

Deviations:

- **Fields that cannot change at runtime.** `FieldInfo::set` writes only through `std::atomic<T>::store` or `ConfigValue<T>::set` (pattern
  maps: `setMap`, through `ConfigValue`). No new locking. A plain field has no `set`, and `//configure <category> <field> <value>` on it
  answers "`<Class>.<FIELD>` cannot be changed at runtime in the C++ port." (Java changes it). The fields affected are the six
  plain fields of commons' DatabaseConfig, which only Config::load writes, under its load lock: `DATABASE_URL`, `DATABASE_USER`,
  `DATABASE_PASSWORD`, `DATABASE_CONNECTIONS_MAX`, `DATABASE_TIMEOUT`, `DATABASE_SOCKET_TIMEOUT`. They are still listed and shown.
  `ConfigDescribeTest.OnlyThePlainDatabaseFieldsCannotBeSet` pins the list; `ConfigureCommandTest.APlainFieldCannotBeChangedAtRuntime`
  the refusal.
- **Bound fields only.** Java's `findStaticFields` lists every static field of the class, annotated or not; the C++ lists the named binds,
  in bind order (Java: declaration order). CommonsConfig's `scriptCompilerCaching` is a local in the C++ bind (Java: a field), so it is
  an unnamed bind and not listed.
- **The C++-only RuntimeConfig** is a category (`runtime`), since `Config::getClasses()` lists it.
- **Value text.** Regular expressions print the source text they were bound or set from (Java `Pattern.toString()`; std::regex keeps none):
  a registry by field address in ConfigurableProcessor.cpp. Hash sets and hash maps (Java HashSet/HashMap) print sorted; Java prints its
  hash order. An InetSocketAddress prints "/host:port" (Java's form for an address made from a literal IP).
- **A TransformationException without a cause** (none is thrown by the transformers) gives "Could not access ..." as Java's
  NullPointerException of `e.getCause().getMessage()` would.

## C++-dev only: the difficulty menu example (owner, 2026-10-20, lane A, branch `dev/difficulty-menu-example`)

A deliberate deviation from Java, for C++-dev only. It is a small working example of a custom difficulty choice, not the full hard-mode
design. It is off by default: `gameserver.custom.difficulty_menu.enable = false` (RuntimeConfig::DIFFICULTY_MENU_ENABLE, C++-only), and
then Java's entry runs unchanged.

Flow with the switch on (custom/difficulty/DifficultyMenu):
1. **Entrance.** Fire Temple's entrances are portal_dialog npcs: 730069 (Elyos) in Eltnen and 730047 (Asmodians) in Morheim
   (portal_template2.xml, loc 3201000). Their entry dialog (PortalDialogAI.onDialogSelect, dialog 10000) normally calls
   `PortalService.port(path, player, npc)`. For a path into map 320100000, `DifficultyMenu::offer` sends an HTML poll instead
   (`HTMLService::sendData`, SM_QUESTIONNAIRE, in surveyTemplate.xhtml's poll markup, built in C++ so no data file is added). Its two
   reward-item choices stand for Normal (110101217, Fire Temple Tunic) and Hard (110501122, Fire Temple Hauberk); nothing is given.
2. **Choice.** The poll's answer comes back as CM_QUESTIONNAIRE, handled by `HTMLService::getReward(player, messageId, items)`. For the open
   menu's message id, `DifficultyMenu::onAnswer` takes it before the guide and survey reward paths. A poll closed without a choice ends the
   menu.
3. **Confirm.** SM_QUESTION_WINDOW 902050 "Enter %WORLDNAME0 (Difficulty: %1)?" with Fire Temple and "Normal" (902051) or "Difficult"
   (902052), through `AIActions.addRequest` as Beshmundir's Walk asks; the client cancels it beyond 5 m of the portal.
4. **Enter.** On Yes, Java's `PortalService.port(path, player, npc, difficult)` with difficult 0 (Normal) or 1 (Hard). Its group rules
   and `InstanceService.getNextAvailableInstance(mapId, difficult, maxPlayers)` are Java's. A group that already has an instance enters
   it in the mode it was created with.
5. **Hard.** A Fire Temple instance created during the Hard entry (`DifficultyMenu::difficultyOfNewInstance`, the entering thread's value)
   is Hard. FireTempleInstance then gives every spawned npc twice its max HP and half again its physical and magical attack
   (StatSetFunctions, as the Eternal Challenge adapts its npcs), and on entry tells each player "Fire Temple - Hard: enemies have
   doubled health and stronger attacks." (center message).

Hooks into ported files: PortalDialogAI.onDialogSelect (the offer before `PortalService::port`), HTMLService.getReward (the answer) and
FireTempleInstance (`onSpawn`, `onEnterInstance`, the difficulty). Tests: `tests/handlers_inst_1/DifficultyMenuTest.cpp` (5 cases):

## C++-dev only: instance scoring, switched on for the Fire Temple Hard example (owner, 2026-10-20, lane A, branch `dev/instance-scoring`)

A deliberate deviation from Java, for C++-dev only. It is a reusable helper, `custom/instance/InstanceScoring`, owned and wired by an
instance handler. Both switches are C++-only RuntimeConfig keys and default to off:
`gameserver.custom.instance_scoring.enable` and `gameserver.custom.instance_scoring.dp_panel`.

- **Countdown.** `start` (once) sends SM_QUEST_ACTION(0, seconds), the client's timer bar, as Roah's 15-minute bar does. `finish`
  clears it with SM_QUEST_ACTION(0, 0).
- **Points per kill.** `onKill` weighs the npc by kind from a table in `Settings`:
  - boss: 200 points, for a HERO or LEGENDARY rating or one of the instance's named `bossNpcIds`;
  - named or elite: 30 points, for an ELITE rating;
  - normal: 10 points.

  Each kill is announced with STR_MSG_GET_SCORE(npc name, points), as DarkPoetaInstance.java:89-92 does.
- **End and rank.** The run ends when one of `finalBossNpcIds` dies or when the handler's timer task fires. The rank uses Dark Poeta's
  1-8 shape (DarkPoetaInstance.java:95-115), scaled to the time limit:
  - rank r (1-4) needs more than 1/2, 3/8, 1/4 or 1/8 of the time left, and at least `pointThresholds[r-1]` points (default 4000, 3200,
    2400, 1600);
  - the final boss killed in time gives at least rank 5;
  - the time out gives rank 8.
- **Result line.** Every player inside gets a chat line (GOLDEN_YELLOW): `[<title>] Rank <r> - <points> points, <m>:<ss> left`.
- **Rewards.** Every player inside gets the rank's items from `Settings.rewards` (ItemService.addItem, inventory overflow allowed).
- **The experimental panel** (`dp_panel`). The score also broadcasts SM_INSTANCE_SCORE with Dark Poeta's map id (300040000) and
  DarkPoetaScoreWriter's layout: our points, kills, rank and progression, with the time left. It is sent at the start, at each kill and
  at the end. This is an experiment to see whether the client draws Dark Poeta's panel in another map; it is not a finished feature.
- **Fire Temple Hard.** A Hard instance (the difficulty menu example) with scoring on has these settings:
  - a 20-minute countdown from the first entry;
  - the seven named bosses of onInstanceCreate count as bosses: 212839, 212842, 212840, 212843, 212841, 212845, plus Kromede in either
    form (212846, 214621);
  - Kromede ends the run.

  Normal, and Hard with scoring off, are unchanged. The rewards are modest existing level-40 consumables:

  | Rank | Rewards |
  |---|---|
  | 1 | 10 x 162000049 Greater Recovery Serum, 20 x 162000005 Greater Life Potion |
  | 2 | 5 x 162000049, 15 x 162000005 |
  | 3 | 10 x 162000005, 10 x 162000010 Greater Mana Potion |
  | 4 | 5 x 162000005 |
  | 5 | 2 x 162000005 |
  | 6 to 8 | none |

  The point thresholds suit Fire Temple's spawns: about 120 normal, 70 elite and 7 named npcs, so up to about 4,700 points.
