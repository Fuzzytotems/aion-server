## Wave 5a (player-events lane, m5a-plan.md E1-06)

Ported M5a subset: SiegeService (constructor with both branches, updateNextStateUpdateTime, initSieges up to the enabled check,
getSecondsUntilNextFortressState, getRemainingSiegeTimeInSeconds, getSiege x2, isSiegeInProgress, getOutpost, getFortress, getArtifact,
getStandaloneArtifacts, getFortressArtifact, getSiegeLocation, getSiegeLocations(worldId), findFortress, onPlayerLogin guard),
SiegeLocation.getInfluenceValue and the new class `model/siege/Influence.{h,cpp}` (all methods). Tests: `tests/siege`.

| Area | Java | C++ | Reason |
|---|---|---|---|
| `SiegeService` location maps | The fields alias `DataManager.SIEGE_LOCATION_DATA`'s maps (or `Collections.emptyMap()`) | The service's `HashMap` shims are filled with the same location objects; disabled: they stay empty | The frozen header declares member shims. Nothing writes the maps after construction |
| `SiegeService.agent` | Assigned only in the enabled branch (null otherwise) | `const Ref` initialized in the member initializer list from the same condition | A const member must be initialized there |
| `Influence.influencesByWorld` | `LinkedHashMap` built by `calculateFortressWorldInfluences` over `SiegeService.getSiegeLocations().values()` (the data holder's `LinkedHashMap`, i.e. the order of siege_locations.xml) | `RcLinkedHashMap` (fieldmap guesses `HashMap` from the declared `Map`; lint waiver), filled in the iteration order of `SiegeService::locations` | The insertion order is kept, but its source is not Java's: the frozen `SiegeService::locations` is a `runtime::HashMap`, so the world ids come out in an arbitrary order and SM_INFLUENCE_RATIO writes them in that order. Accepted risk of `docs/porting/header-requests.md` 5a-pre-10 (a `LinkedHashMap` was rejected because D1 keeps sieges off the M5a path); to be revisited with plan O-05 |
| `SiegeService.getSiegeLocations(int worldId)` | Returns a `LinkedHashMap` in the iteration order of the locations map | The frozen header returns `std::map`, i.e. sorted by location id | Same source as the row above: the order a caller sees differs from Java's. No M5a caller (sieges are disabled); revisit with O-05 |
| `Influence.getInfluenceRelevantWorldIds` | The live key set | A snapshot vector in the map's order | Callers only iterate it |
| `Influence.getInstance` | Created by the static initializer | Function-local static, created on first use | The constructor reads SiegeService and static data, which must not run before `main` |
