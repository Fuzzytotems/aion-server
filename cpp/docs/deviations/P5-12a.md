### Kept Java races (stage-2 fixer run)

`SiegeLocation.onEnterZone` carries a `// java-race` marker (runtime-architecture.md §3.7): Java's `containsKey`/`put` guard
(SiegeLocation.java:209) is not atomic, and the lock-per-operation shims make each call safe without making the pair atomic. The consequence is
Java's: a lost race, or an entry `onLeaveZone` kept because the creature was still inside another zone of the location, leaves the previous
`Ref` in `creatures`/`players`. Both maps are keyed by object id, so the entry is replaced on the next enter after the removal; the removal hook
itself is sound (`ZoneInstance::onLeave` takes the creature out of its own map before calling the handlers, and `World::despawn` revalidates the
zones after `setIsSpawned(false)`), which is what `cycles.toml` resolves as `java-hook: SiegeLocation.onLeaveZone`. `VortexLocation.onEnterZone`
has the same guard and the same marker (docs/deviations/P5-12b.md).

### AION_PARTIAL / unported on purpose

Still no `AION_PARTIAL` site in P5-12a. `FortressLocation.checkForBalanceBuff` reaches `EffectController.hasAbnormalEffect` (P5-03,
`AION_UNPORTED`) and `SkillEngine.applyEffectDirectly` only for a **vulnerable** fortress with a non-zero faction balance, which

stays `AION_UNPORTED` (it needs `TeleportService.moveToBindLocation` and `Kisk.getController().die()`, plan O-05).
