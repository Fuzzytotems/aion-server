# P5-02 skills: deviations

## Wave 5a (stats-skills lane, m5a-plan.md B-05, B-06)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `SkillEngine.applyEffectDirectly(SkillTemplate, int, Creature, Creature)` | Creates the effect, initializes and applies it, returns it | `AION_PARTIAL("passive skill effects are not applied yet (M5a O-09)")`, returns null | Effect application is M5b work (m5a-plan.md D3, O-09); the only M5a caller (`PlayerEnterWorldService.activatePassiveSkillEffects`, `SkillLearnService.onLearnSkill` for passives) ignores the result. The other overloads stay `AION_UNPORTED` |
| `PlayerSkillEntry(Player, int, int, PersistentState)` | Delegates with skillType 0, then assigns `skillType` in the body | Computes the skill type from the learn templates first and delegates with it | `skillType` is a `const` member (PlayerSkillEntry.h); the value and the lookups are Java's |
| `NpcSkillList.initSkillList`, a template whose skill is missing from `SKILL_DATA` | Logs `Missing skill <id> for npc <npcId>` and removes the template from the shared `NpcSkillTemplates` list of the static data, so the next npc of that id neither warns nor sees it | Logs the same line and skips the template; the static data is not changed | The bound static data is immutable in C++. The skill list of every npc is the same as Java's; only the warning is logged once per npc instance instead of once per npc id. It also removes Java's race: `spawnAll` builds these lists on the ForkJoin pool, where Java mutates one shared `ArrayList` from several threads (`// java-race` would not be fixable in place). Test: `NpcSkillListTest.SkillsAndPrioritiesOfAnNpcWithSkillTemplates` |
| `NpcSkillTemplateEntry.canUseNextChain(Npc owner)` | `owner != null && ...` | The parameter is a reference, so only the time comparison is left | The frozen `NpcSkillEntry` header declares `Npc&`; a null owner is the caller's error |
| `PlayerEffectController.addSavedEffect` | Creates the `Effect`, `put`s it into the effect map, starts it and sends `SM_ABNORMAL_STATE` | Java's checks are ported; the restore itself is `AION_PARTIAL("a saved effect is not restored: ...")` | `EffectController.put`, `Effect.addAllEffectToSucess` and `Effect.startEffect` are M5b work (O-09). `PlayerEffectsDAO` calls this once per stored row while the character loads, so an unported body would abort enter-world (plan D3 forbids that); nothing writes `player_effects` at M5a, so the D1 profile never reaches the stub. Test: `PlayerSkillLearnTest.SavedEffectsAreSkippedWithAWarningInsteadOfAbortingTheLogin` |

### AION_PARTIAL sites (for tests/scenario/m5a_partial_allowlist.txt)

- `skillengine/SkillEngine.cpp` `SkillEngine::applyEffectDirectly(const SkillTemplate*, int32_t, Creature&, Creature&)` (every passive skill of
  enter-world and of a learned passive skill)
- `controllers/effect/PlayerEffectController.cpp` `PlayerEffectController::addSavedEffect` (only for a stored effect row, i.e. never for a fresh
  D1 character)

### Ported outside the planned subset

`NpcSkillTemplateEntry` (new class) and `NpcSkillList::initSkillList` for npcs that have `npc_skills` rows: without them every spawn of such an
npc threw `UnportedException` from the `Npc` constructor, which ended `SpawnEngine.spawnAll` and with it the whole startup. `conditionReady` and
`fireOnEndCastEvents` of the new class stay `AION_UNPORTED` (they need the effect controller, `TribeRelationService` and `SpawnEngine`); D2 gives
every npc `DummyAI` at M5a, so no npc casts. `Event.isEventEffectForceType` (P5-12b) had to be ported for `addSavedEffect`'s first line.
