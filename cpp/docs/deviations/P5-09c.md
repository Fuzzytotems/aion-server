# P5-09c mail and craft: deviations

P5-09 was split into P5-09a (drop, rewards, passport, bonus and faction packs, guide), P5-09b (trade and market) and P5-09c (mail and craft:
`services/mail`, `services/craft`, `RecipeService`, `model/craft`) for M5c (m5c-plan.md D1, I-01). The rows of the shared `P5-09.md` from waves
5a to M5b-3 stay there; this file holds P5-09c's rows from M5c on.

### Java behaviour kept on purpose (pinned by the tests)

- **A store that fails after the sender paid** (MailService.java:149-162, m5c-plan.md risk 1): the kinah (and a whole stack's item or a split
  stack's count) leave the sender before `InventoryDAO.store` and `MailDAO.storeLetter`; when either answers false the send ends there and nothing
  is given back, and no letter exists. Tests: the `MailDAO.storeLetter` arm by `Oracle/MailCommissionTest.*`'s rows without an item (without a
  database the letter's store fails: the total is taken, no `SM_MAIL_SERVICE`, no letter; in the rows with an item `InventoryDAO.store` fails
  first, so they do not tell the two arms apart), the `InventoryDAO.store` arm by `MailServiceTest.AFailedItemStoreSendsNoLetter` (with the
  database: a row with the new item's object id makes its INSERT fail while the letter's row could be written).
- **A count below 1, or an object id of 0, attaches nothing** (MailService.java:86): `CM_SEND_MAIL` reads the count with `readQ`, so a client
  can send a negative one; the item is never looked up, the letter costs the plain price and the stack stays whole (a looked-up item would pass
  `getItemCount() < count`, lower the commission and "decrease" the stack by a negative count). Tests: `MailServiceTest.ACountOfZeroAttachesNoItem`,
  `MailServiceTest.ANegativeCountAttachesNoItem`.
- **The recipient is refused before any item check** (MailService.java:71-76, then :86-103). Test:
  `MailServiceTest.ARecipientOfTheOtherRaceIsRefused` (an unknown object id to the other race answers `MAIL_IS_ONE_RACE_ONLY`).
- **Only a packed item is unpacked** (MailService.java:143): an unpacked item (pack count -1) takes its disposition items like any untradeable
  item and keeps -1; flipping it would pack it, tradeable, again. Tests: `MailServiceTest.APackedItemNeedsNoDispositionAndIsUnpacked`,
  `MailServiceTest.AnUnpackedItemIsNotPackedAgain`.
- **An online recipient's letter counter is set to his mailbox's size**, not raised by one (SystemMailService.java:124), and an online recipient
  whose mailbox is not loaded yet is left alone (:121: the letter is stored, `onPlayerLogin` loads it). Tests:
  `MailServiceTest.AnOnlineRecipientGetsTheLetterAtOnce` (a stale counter of 5 over an empty mailbox becomes 1),
  `SystemMailServiceTest.AnOnlineRecipientWithoutAMailboxIsLeftAlone`.
- **"fix for kinah dupe"** (MailService.java:241-251): the letter loses its kinah and is stored before the kinah is added; when the store fails
  the kinah is audited and never added, and it is gone from the letter. Tests: `MailServiceTest.TheKinahIsStoredBeforeItIsAdded` (no database),
  `MailServiceTest.TakingTheKinahStoresTheLetterThenPays`.
- **The `isEquipped` refusal is out of reach for a worn item** (MailService.java:87-97): the inventory never holds a worn item (Equipment does),
  so its object id is "used" (`STR_MAIL_SEND_USED_ITEM`); `STR_MAIL_SEND_CAN_NOT_SEND_EQUIPPED_ITEM` answers only an inventory item flagged
  equipped. Test: `MailServiceTest.AnEquippedItemIsRefused`.
- **An untradeable item without a disposition** ("can not be traded, hack") and one whose disposition items are short end the send silently,
  after the price check and before anything is taken. Tests: `MailServiceTest.AnUntradeableItemWithoutADispositionIsNotSent`,
  `MailServiceTest.AnUntradeableItemTakesItsDispositionItems`.

### Java behaviour kept on purpose (pinned by the tests)

  `CraftServiceTest.TheMaterialsAreTheFirstAlternativeWhoseFirstItemWasSent` (the second step) and `CraftType1WantsTheEnhancementStoneOfTheProfession`.
  The fix, if any, is the owner's.
- **The morph with a known non-static target loses its materials and DP**: checkCraft skips the target check for skill 40009, consumes the
  alternative and `startCrafting` spends the DP before the cast throws (:109-123). Test: `CraftServiceTest.TheMorphsTargetIsCastToAStaticObject`.

  refusal's `ITEM_DATA.getItemTemplate(0).getL10n()` throws, before anything is taken (:216-219). Test: `CraftType1WantsTheEnhancementStoneOfTheProfession`.
- **A crit count past the combo products throws after the xp was given** (:63-70, `RecipeTemplate.getComboProduct`). Test:
  `CraftServiceTest.ACriticalCraftMakesTheComboProduct`.
- **The craft cooldown is wall-clock time** (`System.currentTimeMillis`, :92; `commons::utils::currentTimeMillis`, as `Cooldowns` compares).
  Test: `CraftServiceTest.ARecipeWithACraftDelayStartsItsCooldown`.
