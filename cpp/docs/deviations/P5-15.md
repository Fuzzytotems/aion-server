# P5-15 client packets A-K: deviations

## M5b-2, stage 1 part 1 (player-side lane, m5b2-plan.md P-02)

`CM_CASTSPELL` is a **new file** (before M5b-2 a client's skill bar reached the factory's "not ported yet" warning). `readImpl` and `runImpl`
are CM_CASTSPELL.java:36-109 statement for statement, including the four target arms (0/3/4 an object id, 1 a point, 2 a point and eight
dropped floats, anything else nothing), the unsigned reads, and the order of the early returns: dead, spell id 0 (cancel), pet order skill
without a pet, unknown or passive template, then the protection task, the item-use cancel, the too-early audit and
`PlayerController::useSkill`. **No behavioural deviation.**

| Area | Java | C++ | Reason |
|---|---|---|---|
| `receiveTime` | `private final long receiveTime = System.currentTimeMillis();` - a field initializer, run by the constructor the factory calls reflectively when the packet arrives (AionClientPacketFactory.java:319) | Initialized in the constructor's member initializer list, which `AionClientPacketFactory` runs when the packet arrives | Same moment; noted because it is the value the too-early check compares |
| `player.getLastSkill().getSkillId()` | Java dereferences the template the comment says "cannot be null" | An explicit `throw runtime::NullPointerException(...)` when it is null | `getLastSkill()` returns a raw `const SkillTemplate*` (static data), whose null dereference would be undefined behaviour rather than Java's exception |
| `CM_CASTSPELLTestAccess` | - | C++ only: a `friend struct` declared in `CM_CASTSPELL.h`, defined in `tests/cm_ak/CastSpellPacketTest.cpp`, reads the fields `readImpl` decoded | Java's fields are private without getters, and until `SkillEngine::getSkillFor` is ported (m5b2-plan.md S-01) nothing downstream of `runImpl` makes the level, the target arm or the hit time observable. The precedent is `ChatProcessorTestAccess` |

**Where the packet stops today.** `runImpl`'s last statement is `PlayerController::useSkill`, whose first statement is
`SkillEngine::getSkillFor` - `AION_UNPORTED` until S-01 (part 2). So a real client's cast now ends in an `UnportedException` that
`AionClientPacket::run` logs as "Error handling client packet", where it used to end in the factory's "not ported yet" warning. The scripted gates
(`gs.scenario.m5a`, `gs.scenario.m5b`) send no `CM_CASTSPELL`, so neither sees it. `tests/cm_ak/CastSpellPacketTest.cpp` pins the boundary
(`AnActiveSkillEndsTheProtectionCancelsTheItemUseAndReachesTheEngine`, `SpellIdZeroCancelsTheCastInProgress` through `Skill::cancelCast`) and
says, in its header, what each case becomes when S-01 and S-02 land.
