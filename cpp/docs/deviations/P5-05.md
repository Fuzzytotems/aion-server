# P5-05 AI framework: deviations

## Wave 5a (world-engines lane, m5a-plan.md W-01)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `AIEngine.validateScripts`, handler checks | Reflection: "Faulty AI handler: ... missing generic owner type info" / "... missing constructor taking owner" | Not checked at run time: the `AION_AI` marker checks the owner type and the constructor at compile time (HandlerRegistry.h `AIHandlerClass`) | No reflection |
| `AIEngine.validateScripts`, missing template AI names | `String.join(", ", npcAINames)` of a `HashSet` (unspecified order) | The distinct names sorted | Deterministic message |
| `AIEngine.registerAI` | `aiHandlers.putIfAbsent(name, class)`, IllegalArgumentException for a duplicate name | The registry (sorted by name, unique names) stands for the map: an entry is accepted when the registry holds exactly that entry under its name, or none | The compiled handler registry replaces the class map (AIEngine.h) |
| `AbstractAI.onCreatureEvent`, event recursion guard | `throw new StackOverflowError(...)` (an `Error`, not caught by `catch (Exception)`) | `commons::utils::Exception` with the same message | C++ has no Error hierarchy; callers that catch `std::exception` also catch it |
| `AbstractAI.handleCreatureEvent`, `(Player) creature` for DIALOG_START/DIALOG_FINISH | ClassCastException "class <FQN> cannot be cast to class ...Player" | `runtime::ClassCastException` whose message starts with the C++ type name | No Java class names at run time |
| `AbstractAI.setStateIfNot`, DIED to FIGHT with logging | Logs each `StackTraceElement` of a new Throwable | Logs each line of `std::stacktrace::current()` | Stack trace format |
| `AbstractAI.getName` | `@AIName` annotation of the class, "noname" without | The registry entry `newAI` stored (`setRegistryEntry`), "noname" without | No annotations (AbstractAI.h) |

## Wave 5b-1 (ai lane, m5b-plan.md A-00..A-08)

The warn-mode `DummyNpcAI` of A-00/D15 is a deviation of the `gameserver.dev.missing_ai_handlers` key and has its row in
[P4-01.md](P4-01.md) next to the other rows of that key.

| Area | Java | C++ | Reason |
|---|---|---|---|
| `AIEngine.reload` (A-07) | `scriptManager.shutdown(); aiHandlers.clear(); init();` - the `data/handlers` sources are unloaded and compiled again | `init()`. There is nothing to unload and nothing to clear: the handlers are compiled into the binary and `handlers::aiHandlerEntries()` is a fixed table, so re-registering them is what `init()` does. `//reload ai` (admincommands/Reload.java:75) therefore re-runs `validateScripts` and logs the handler count, as it does in Java, but cannot pick up an edited handler | `commons.scripting` is not ported (CONVENTIONS.md "Unported Java features") |
| `HpPhases.tryEnterNextPhase(T ai)` (A-04) | `<T extends NpcAI & PhaseHandler>`; javac erases `T` to `NpcAI` and inserts a checkcast to `PhaseHandler` where the AI is used as one | `void tryEnterNextPhase(NpcAI& ai)` with an explicit `dynamic_cast` to `HpPhases::PhaseHandler` at the `handleHpPhase` call, throwing `runtime::ClassCastException` with the C++ type name | The erasure rule of hub-headers.md §8.1 applied to a generic method with an intersection bound; same erasure, same throw point |
| `HpPhases.tryEnterNextPhase`, `ai.getLifeStats()` (A-04) | `NpcAI.getLifeStats()` is `protected`, which in Java is also package access, so `HpPhases` (same package) may call it | The port spells the delegation out as `ai.getOwner().getLifeStats()`, which is the body of `NpcAI::getLifeStats` (NpcAI.java:51-53) | C++ `protected` is per class, not per package; same call, same object, no header change |
| `ShoutEventHandler`, the shout lists (A-01) | `NpcShoutData.getNpcShouts(...)` may return `null`, which is passed on to `NpcShoutsService.shoutRandom`, whose first statement is `if (shouts == null \|\| shouts.isEmpty()) return;` | `getNpcShouts` returns `std::optional`; a `nullopt` is passed on as the empty vector, because `shoutRandom` takes a `const std::vector&` (NpcShoutsService.h, P5-14) | `shoutRandom` cannot tell null from empty (NpcShoutsService.java:60), so the two are the same call |
| Java package-private and private statics of `ai/handler` and `ai/manager` (A-01, A-02) | `protected static` (package access) `CreatureEventHandler.checkAggro`, `AttackManager.chooseAttack`, `SimpleAttackManager.attackAction`, `SkillAttackManager.skillAction`, `WalkManager.findNextRoutStep` / `findClosestRouteStep` / `findNextRouteStepAfterPause` / `chooseNextRouteStep`; `private static AttackManager.checkGiveupDistance` | All public, with the Java access noted at the declaration. The bodies are unchanged and nothing outside their own class calls the widened ones except `TargetEventHandler::checkAggro` (which Java's package access also allows) and the decision-table tests of m5b-plan.md A-08 | C++ has no package access, and the two decision tables A-08 requires (`checkAggro`, `checkGiveupDistance`) cannot be reached any other way: the gate scripts one path and a table needs the rows it does not take |
| The scheduled AI tasks (A-01, A-02, A-05) | `ThreadPoolManager.schedule(new AggroNotifier(...), 500)`, `schedule(new SimpleCheckedAttackAction(npcAI), delay)`, `scheduleAtFixedRate(new FollowSummonTaskAI(...), 1000, 1000)` and the four scheduled lambdas retain their captures until they run | The same, plus a `runtime::Pin` on the creature (and on the AI part where the lambda captures it) | The pin adds no retention Java does not have - the task's own `Ref`s already hold the objects - but it lets the leak census and the zombie breaker attribute a pending task to its owner (runtime-architecture.md §5.4). The precedent is `LifeStatsRestoreService.cpp` |
| `SkillAttackManager.cantUseSkill` (A-02, m5b-plan.md D4) | Reads `EffectController.isInAnyAbnormalState` / `isAbnormalSet` and `SkillTemplate.getType` and answers whether the npc may cast | An `AION_PARTIAL` that answers **true** ("cannot use"), the refusing half of Java's two answers | The whole class needs the skill engine of M5b-2 (O-01/O-03). `GeneralNpcAI::chooseSkillAttack` is the other half of D4 and answers false, so a correct M5b-1 server never asks for a `SKILL_ATTACK` and never reaches this body; the gate asserts its hit count is 0 (m5b-plan.md §6.1 §B). The precedent for the refusing answer is `PlayerRestrictions::canUseSkill` (P5-13) |
