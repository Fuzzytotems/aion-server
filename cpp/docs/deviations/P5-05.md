## M5c stage 0 (dialog lane, m5c-plan.md D-05)

`PostboxAI` is a **new handler** (`handlers/ai/PostboxAI.{h,cpp}`, `AION_AI(PostboxAI, "postbox")`): `handleDialogStart` sets the mailbox
state `REGULAR` and sends `SM_DIALOG_WINDOW(page 18 = MAIL)` in talk range (else the warehouse too-far message), `handleDialogFinish` sets it
`CLOSED` (PostboxAI.java:22-30). Its states come from the new constants class `services/player/PlayerMailboxState.h` (P5-08; `fwd.h` already
declared it). **No behavioural deviation**; a player without a mailbox is Java's `NullPointerException`. It answers all 7 `ai="postbox"`
templates, so mailboxes in 10 or more maps (Sanctum and Pandaemonium among them) now open a mail window whose client packets wait for stage 1
(m5c-plan.md W-36). Startup no longer warns "No AI found for name postbox". Tests: `tests/handlers_ai_core/PostboxAiTest.cpp`.

## Ascension lane (2026-09-28 night lanes, on the M5d engine overlay; m5d-plan.md A-01 and an A1 file lease)

Two **new handlers** for the retail ascension route (quests 1006 / 2008 and 1007 / 2009), prepared early to merge after M5c stage 2:

- `AbyssGuardSimpleAI` (`handlers/ai/AbyssGuardSimpleAI.{h,cpp}`, `AION_AI(AbyssGuardSimpleAI, "simple_abyssguard")`, m5d-plan.md A-01),
  5 bodies (AbyssGuardSimpleAI.java:23-76): `canHandleEvent` (CREATURE_MOVED in every state but FIGHT, the rest to the superclass),
  `handleCreatureSee` / `handleCreatureMoved` (an npc goes to the private npc-vs-npc `checkAggro`, a character to AggressiveNpcAI's rule),

- `AscensationNpcAI` (`handlers/ai/quests/AscensationNpcAI.{h,cpp}`, `AION_AI(AscensationNpcAI, "ascensationquestnpc")`), 1 body
  (AscensationNpcAI.java:20-23): `modifyOwnerDamage` answers 1. The file is **chunk A1's**; this lane holds a file lease on

**No behavioural deviation** in either. What registering them changes: the 859 `simple_abyssguard` templates (870 spawn spots at startup, 997
in all spawn files, m5d-plan.md D5) leave the warn-mode `DummyNpcAI`. They talk (Jucleas 203752 of 1007, the Pandaemonium guards 204075,
204080-204083 and 204182 of 2009, the 9 start-map givers of 16 XML quests), fight back, aggro characters of the enemy race as AggressiveNpcAI
does, and aggro enemy npcs in their aggro range. A static estimate over the startup spawn files (the Java `Npc.isEnemy` rules, level >= 2,
center-to-center distance < srange) finds 3 guard/npc pairs in range, all in Morheim, and none on Poeta, Ishalgen, Sanctum or Pandaemonium;
walkers and chasing monsters are not in it. The four `ascensationquestnpc` npcs (211042, 211043, 205040, 205041) have no static spawn - only
the 1006 / 2008 handlers spawn them (211042 and 211043 at _1006Ascension.java:168-171 and :223, 205040 and 205041 at
_2008Ascension.java:230-233 and :76) - so that name changes nothing until the handlers land. Startup no longer warns "No AI found" for
either name.
