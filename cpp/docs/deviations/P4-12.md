## game-server / player model (P4-12, `model/gameobjects/player`, `model/account`)

| Area | Java | C++ | Reason |
|---|---|---|---|
| `AbyssRank` initial persistent state | `null` until `doUpdate` or the DAO sets it; `setPersistentState(UPDATE_REQUIRED)` stores it because the state is not `NEW` | `NOACTION` before the constructor's `doUpdate`; the setter treats it like `null` (not `NEW`), so a transferred character (`CMT_CHARACTER_INFORMATION`, last update 0) becomes `UPDATE_REQUIRED` as in Java. Only `getPersistentState()` before any store differs (`NOACTION` instead of `null`, which Java callers would dereference) | `Field<PersistentState>` has no null; the frozen member keeps its type |
| `MotionList` with a motion id missing from `Motion.motionType` | `activeMotions.put(null, motion)` / `remove(null)` use a null key | `std::out_of_range` from the constant table | No null key for `int32_t`; only invalid client or DAO ids reach it |
| `Player.getAttackType` for a weapon template without an attack type | Returns `null` | Throws `std::bad_optional_access` | The frozen `Creature::getAttackType` returns `ItemAttackType` (no null); item templates of weapons define the attack type |
| Null `Timestamp`s read by `PassportsList.getPassport`/`hasPassportForDay`, `PetList.loadPets` and `Mailbox.getNewSystemLetters` | `NullPointerException` | `std::bad_optional_access` | Nullable timestamps are `std::optional` (hub-headers.md §6); both only report corrupt rows |
| `LogoutBreakers` step failures | No Java counterpart | Each step runs even if an earlier one threw: an `UnportedException` (a breaker helper of a chunk that is not ported yet) is skipped silently, any other exception is logged with the step id and the object id | `noexcept` breakers must not stop at the first failing step (runtime-architecture.md §5.3) |
| `LogoutBreakers::breakZombieEdges` | No Java counterpart | Cuts and reports target, known objects, walker group, kisk, the account warehouse actor while the zombie is that actor, ride observers, summon, pet and the observer lists (reported once as `observers`); resets the inventory and warehouse actors, the stance observer and the IdianStone listeners without reporting them | The inventory and warehouse actors are the owning player itself; one emptiness query covers both observer lists (header requests player-1 to player-3, docs/porting/header-requests.md) |
| `PetList` test seam | `PlayerPetsDAO.getPlayerPets` only | `PetList::setPlayerPetsLoaderForTests` replaces the DAO read while a test sets it; server code never sets it | `create<Player>` in tests before the DAO body (P4-14) exists; no behaviour change for the server |
| `MotionList.setActive(0, type)` without active motions | Sends `SM_MOTION(0, type)` to the owner, then broadcasts `SM_MOTION(ownerId, null)`, whose `writeImpl` throws a `NullPointerException` on each recipient's write thread, so no recipient gets it | Sends `SM_MOTION(0, type)` to the owner and skips the broadcast | The observable result without the write-thread exception; test `PlayerCreationTest.ReplaceableParts` |
| `Account` player iteration (`getPlayerAccDataList`, `iterator`, range-for; `SM_CHARACTER_LIST`, `LoginServer` account updates) | `HashMap<Integer, PlayerAccountData>` bucket order (`(h ^ h >>> 16) & (capacity - 1)`, then insertion order) | Ascending object id (`PartMap` order) | The frozen `PartMap` member iterates in key order; deterministic like `GameServerTable` (login server). Emulating the bucket order is possible if the client turns out to care |
